# YouTube single video CLI acquisition

## Scope and ownership

Connect a selected source-video requirement to an explicitly submitted YouTube URL using local yt-dlp, without API keys. Inspect metadata first; an independent explicit action acquires one supported CC BY video and records a rights-only automatic policy observation. This is planning media intake, not reference calibration, source/semantic approval or production authority.

Root writes this card before/after implementation. One implementation delegate owns product and tests; separate read-only verifier/reviewer follow. Preserve all existing dirty AI-source bridge and Wikimedia policy changes plus unrelated `next-env.d.ts`. No redelegation.

Allowed: new focused `visualmaker/core/youtube-*.ts` helpers; `visualmaker/core/automatic-rights.ts` only for coherent shared rights-policy application; two new Studio API routes `youtube-inspect` and `youtube-acquire`; new `src/components/studio/youtube-source*.ts*`; integration in `studio.tsx`; focused tests and package diagnostic scripts. Reuse existing attachUpload/atomic store hooks without widening upload limits. Any additional schema/helper edit must be justified to root first.

Forbidden: immutable raw, actual data/media, episode specs/states/approval markers, authentication credentials, OpenAI/AI CLI integrations, dependency installs/upgrades, other repository subfolders, commits/pushes, live YouTube metadata or download calls during validation, browser/server starts or uploads.

## API and data contract

- Strictly guarded localhost/token/origin routes and bounded exact JSON DTOs follow existing source-acquire patterns. Inspect and acquire are explicit separate POST actions. Scope includes exact projectId, baseRevision, requirementId, script hash as appropriate; never trust a client Plan, license, command, binary path or downloaded URL.
- Reuse canonicalizeYouTubeUrl. Only a single canonical YouTube video is accepted; no playlist/channel/search URL, unsupported host, URL credentials or command injection. Only the currently selected source-video candidate's unassigned external/official video requirement may be inspected/acquired. Locked owning scenes or ambiguous sharing fail closed. Revalidate before and after async work and atomically on attachment.
- Public inspect result contains a bounded exact normalized whitelist: schema/scope, canonical URL/video ID, title, channel/creator identifiers, duration, upload date where available, original license label, metadata fingerprint, rights eligibility/reason, productionAuthority=false. No signed media URLs, cookies, raw descriptions, raw stderr, executable metadata, remote image auto-load or invented license version. Unknown/standard/no/free-title licenses can be displayed but are not eligible for this acquisition route.
- Accept the exact supported YouTube CC Attribution license representation observed in extractor metadata, not arbitrary substring matching. Metadata ID/extractor/webpage URL/availability/live/playlist/type must identify the requested public finite video. Retain title, creator/channel, canonical URL, observed license label, retrieval time and fingerprints. YouTube CC BY without a version is never relabeled CC BY 4.0.
- Acquisition requires the exact inspected fingerprint and scope, re-inspects authoritative CLI metadata before downloading, compares all normalized relevant fields, and rejects changed/unknown license. Bind downloaded identity/license again using CLI's actual-download metadata or equivalent post-download reinspection; do not attach if source identity/rights changed. One supported progressive MP4 only, no playlist, live stream, DRM/access restriction bypass, login/cookie/netrc/profile, automatic remote components or general arbitrary URL extractor.
- Size is at most 40,000,000 bytes to match attachUpload; duration at most 600 seconds, dimensions at most 1280x720. Enforce bounded process/network time, output byte limits and cancellation while downloading, not only afterward. Probe actual bytes for a real MP4 video with valid positive duration/dimensions and limits before attachment. No decompression, remux/merge process or unbounded file writes. Prefer stdout byte streaming with fixed format and memory cap; if temp files are necessary, use verified exclusive owned temp targets and safe cleanup.
- CLI execution uses a trusted existing executable resolved/configured locally, shell=false, windowsHide=true, fixed argument arrays and canonical URL after `--`, ignore configuration, disable plugins and non-required external components. No arbitrary request options/paths/env or inherited auth configuration. Sanitize/minimize environment and bound stdout/stderr/time. Return useful installation/unavailable errors without machine paths/secrets. Missing binaries do not create a Plan asset. Tests inject a fake runner; production dependencies cannot be supplied by HTTP.
- Attach bytes + provenance receipt + rights-only automatic observation inside existing transaction/hook; no second non-atomic approval call. Preserve current manual rejection/override protection and hash/context invalidation from the Wikimedia policy. Source and semantic remain pending; productionAuthority=false. Keep full credit metadata in receipt and bounded rationale; never claim downstream credits were published or legal clearance obtained.
- Define a strict new acquire response/client validator rather than mislabeling YouTube as an existing Commons provider/variant. Deliver fresh Plan and review states only when exact byte/scope/revision bindings hold.
