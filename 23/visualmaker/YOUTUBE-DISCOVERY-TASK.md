## API/data contract

- Explicit user POST /api/studio/youtube-search with exact projectId, baseRevision, requirementId, scriptSha256, query. Same localhost/token/origin guards and selected unlocked singleton source-video requirement validation as inspection. Validate before/after asynchronous work. No Plan, executable, flags, search URL, license or candidate IDs accepted from client.
- Query is trimmed single-line 2–120 characters, no controls. User sees/edits requirement queryKo/queryEn before submission; no silent truncation or network on render/query-fill. This is keyword candidate retrieval, not semantic approval/ranking.
- CLI fixed flat search ytsearch5:<query>, skip downloads, max five entries, bounded JSON output. Build trusted arguments internally, retain hardened base flags. Search results yield only validated unique 11-character video IDs; never execute result-supplied URLs. A flat result is NOT license evidence.
- Individually inspect canonical video URLs through the existing metadata whitelist and exact CC label validation. Return only exact YouTube CC Attribution label cards, including unsupported-download cards with rightsEligible=false/reason. Preserve provider order, deduplicate, never fabricate results/fallback rights. Standard/unknown/free-prose licenses excluded. Current inspection's finite/public/10-minute limits remain and are disclosed.
- Overall request deadline at most 60 seconds plus bounded process teardown, propagated cancellation, sequential inspection up to five; stop on stale scope/abort. Malformed search payload fails closed. Non-cancelled individual unavailable/invalid metadata may be skipped; environment/CLI failures are not successful empty results. Return attempted/verified/excluded/failed counts and partial status without leaking raw stderr/URLs. Response has exact schema, scope, query, candidates, counts, productionAuthority=false. No asset/store mutation.
- Candidate selection is an explicit UI action feeding existing checked-card/acquire flow. Acquire independently re-inspects metadata, keeps existing atomic attachment and rights-only observation. Discovery itself grants no rights/source/semantic/production PASS.
- Client validates exact response/card/scope/query/counts, duplicate IDs, CC label, stale revision, request epoch and abort. Query changes/close/scope switch cancel and discard stale results; no cross-project/requirement selection. Shared mutation lock still protects acquisition.

## Existing WISE bridge still required

`youtube1/production-studio/backend/media.py` maps canonical source IDs, original SHA-256 and WISE media IDs; its indexer admits rights-confirmed canonical files and its search adapter maps/clamps candidate spans back to those sources. Current VisualMaker assets use separate content-addressed bytes, IDs and pending review state. Reuse that engine deliberately through a verified source-ID / WISE-media-ID / VisualMaker-asset-ID / SHA-256 bridge, not direct cross-store writes or approval translation. A WISE hit remains a candidate span; it is not source, semantic, cut or production approval.

The sibling WISE.md describes a WSL Ubuntu environment, but current read-only host checks found no wise executable on PATH, no listener on the documented default port, no running WISE Docker container and only docker-desktop in the WSL list. These observations do not prove the engine was never installed elsewhere; current runtime is unconfirmed. Do not silently reinstall WSL or download model weights.
