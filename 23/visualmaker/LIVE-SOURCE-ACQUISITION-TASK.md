## API / data contract

- Authenticated local/same-origin Studio API only, existing guard and token header. Reject extra/malformed parameters before provider network requests. No client URL/path/download-host/bypass/approval fields.
- Providers: Wikimedia Commons photos/videos, NASA Image Library photos, Library of Congress photos. Unsupported provider/media combinations return explicit errors, never silently substitute providers/modes. KOGL/Pexels or other providers remain explicitly unimplemented in this bridge until their adapters are integrated.
- GET source-search accepts projectId, baseRevision, requirementId, provider, query and bounded page/media type. Requirements must exist, match requested media type and external/official acquisition, and remain unfilled/editable with no locked owning scenes. Queries are explicit user requests, length-bounded; never auto-send the entire script. Search is metadata-only: no download, archive/database/media writes or eager syncKeylessMedia calls.
- Response uses a versioned schema and exact project/revision/requirement/script-SHA scope. Bounded candidate cards expose provider ID, item page, title, creator/publisher, declared rights/license, media type/dimensions, stable metadata fingerprint, and truthful file-variant information. No arbitrary raw download URL or unlimited provider metadata. Untrusted provider HTML is plain bounded text. Missing metadata stays unknown; never infer Korean locations/official status or license clearance from provider identity.
- Distinguish provider originals from previews/derivatives. Commons acquisition uses imageinfo.url, not iiurlwidth thumbnail bytes. NASA selects a published downloadable asset from the selected item's asset manifest, not a search-preview falsely called an original. LOC chosen image variants are labelled derivative/unknown unless exact original metadata proves otherwise. Preserve this distinction in the provenance receipt; no filename/crop-based original-diversity claims.
- POST source-acquire accepts exact scope plus provider/query/page/media type, selected provider ID and its metadata fingerprint, semanticNote and evidenceOnly. Requery provider metadata and require exact ID/fingerprint/type equality, else 409. Selection may not supply or override download URL, rights, creator, file path or approval. Only one selected asset is fetched.
- Provider endpoints and download hosts are fixed HTTPS allowlists; credentials/userinfo/custom ports and unsafe paths rejected. Reject redirects to avoid unvalidated destinations; verify response URL/content type. Requests have timeout/cancel, bounded JSON before parsing, bounded streaming binary download before allocation (at most existing 40MB upload limit), and bounded result count/concurrency. Unsupported/oversized/missing media fails explicitly. Do not allocate an unbounded response then check its size.
- Revalidate current plan/revision/requirement/lock/empty status before network and before mutation. Reuse attachUpload and its existing decode/hash/transaction semantics. Concurrent edits, already-filled requirements, duplicate bytes and locked scenes fail closed; do not overwrite old assets. Duplicate sources should use existing explicit reuse workflow.
- Receipt records version/provider/provider ID/item URL/query/fingerprint/retrieval time, chosen variant and download SHA; local input hash binds exact bytes. Search and acquisition keep productionAuthority=false; source/rights/semantic reviews remain pending, never approved. Acquiring a file is not production materialization into episode-spec or an active cut root.
- Cancellation/error/stale-revision must not leave an attached asset or unowned staging file. Error text must not expose tokens, paths, arbitrary provider payloads or credentials.
