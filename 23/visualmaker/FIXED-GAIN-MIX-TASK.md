## Technical data contract

Versioned strict contract `visualmaker-fixed-gain-mix-v1`, fixed 48000 Hz/stereo, positive integral `durationSamples` bounded to 48000*600 for this first engine. One voice input plus 1–16 explicitly ordered music/SFX stems. Each input declares a unique safe ID, canonical repository-relative path, SHA-256, bytes and exact expected decoded sample count at the fixed format. Voice starts at sample zero with gain 0 dB and must cover the full duration; require exact decoded count, do not silently trim it. Each stem declares kind music/sfx, integral nonnegative startSample and finite gainDb in [-60,0]; decoded duration must match declaration and fit wholly inside output. No inferred trim, repeat, fade, automation, ducking, normalization, gain defaults, remote URL, arbitrary filter expression or CLI. Unknown fields, duplicate IDs/path identities, empty/invalid streams, unsafe paths/symlinks or input drift fail closed.

Input hashes are technical integrity only. Contract hashing must be deterministic with a documented fixed field ordering; input ordering is semantic and retained. Limit per-input bytes and total decoded output memory/disk explicitly, stream decoding/measurement rather than unbounded stdout or whole-episode arrays. Never reuse caller paths as FFmpeg arguments without safe contained validation. Reject URLs/protocols in paths. Spawn installed FFmpeg without shell, with finite timeout, bounded stderr, abort cleanup and no network input. Reuse existing safe local FFmpeg/process helpers read-only if appropriate; do not broaden their APIs.

## Execution and measurement

Decode actual files to 48 kHz stereo float PCM, count and inspect every finite sample. Sum voice and each fixed-gain stem at its exact sample offset, without automatic level scaling or limiter. Output a technical local WAV (float PCM) plus a receipt only under an exact owned empty temporary output directory; never publish job artifacts. Validate sum peak <= -1 dBFS (a conservative technical engine ceiling, NOT a loudness/quality or platform standard), finite samples and no clipping. Record peak/RMS, clipping count, sample count/rate/channels, input and output bytes/hashes, contract hash and FFmpeg version. Recheck every input after execution. Do not silently resample count drift, trim, clamp or reduce gain to pass. Do not claim AAC/MP4 sample identity or finalization integration; not in this boundary.

Reference: [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html#amix) documents amix normalization defaults and clipping risk when disabled; [adelay](https://ffmpeg.org/ffmpeg-filters.html#adelay) documents sample-based delay. These are mechanism references, not human audio-quality approval. Exact sample arithmetic may be performed in the bounded streaming engine instead of constructing a filter graph.
