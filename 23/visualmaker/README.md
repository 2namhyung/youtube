# VisualMaker — 로컬 장면 설계 작업대

## 실행

저장소 루트에서 실행합니다.

```powershell
pnpm run visualmaker:dev
# http://127.0.0.1:3017/studio
pnpm run visualmaker:check
```

기존 Next.js 15 / React / Node SQLite 기반입니다. 별도 포크·API 키·Python 설치 없이 현재 PC에서 사용할 수 있습니다. 기본 바인딩은 127.0.0.1이며 외부 배포용 인증/다중 사용자 서비스가 아닙니다.

기준 프로그램을 `project/youtube/23`으로 정리하는 절차와 기존 데이터 경로를 사용하는 실행 방법은 [작업공간 정리 계약](WORKSPACE-CONSOLIDATION.md)을 참고하세요. `raw/`와 고유 자료는 옮기지 않습니다. WISE 연결에는 별도의 기존 Python/WISE 실행 환경이 필요합니다.

## 자료 탐색 연결 현황

AI 제안의 검색 브리프를 자료 요구에 연결한 뒤 사용자가 검색어를 확인·수정할 수 있습니다. [YouTube CLI 후보 검색](YOUTUBE-DISCOVERY-TASK.md)은 검색 상위 최대 다섯 건의 메타데이터에서 CC BY 표시를 확인하는 경로이며, YouTube 전체의 CC 영상 전용 검색이나 WISE 의미 검색은 아닙니다. [WISE 연결](WISE-BRIDGE-TASK.md)은 기존 제작실의 정본 자료실을 읽기 전용으로 열어 색인된 원본을 의미 검색하고, 선택한 원본의 바이트·해시·구간을 검증해 가져오는 경로입니다. 두 검색은 명시적 버튼으로 실행합니다. YouTube 수집 자료를 WISE에 자동 색인하는 단계와 실제 WISE 서버를 사용한 수용 검증은 남아 있습니다.

WISE 자료실의 과거 권리 확인은 출처 기록으로만 보존하며 VisualMaker에서는 출처·권리·의미 검토가 모두 대기로 시작합니다. Commons/YouTube의 지원되는 재사용 표시를 바탕으로 한 자동 기록은 [권리 정책](AUTO-RIGHTS-POLICY-TASK.md)의 제한된 사용 조건 관찰이며, 장면 의미·스타일·컷 승인이나 제작 권한을 부여하지 않습니다.

## 사용할 수 있는 기능

- 한국어 대본 입력, 문단 단위 초벌 Beat와 두 표현 대안. `[메모]` 줄과 단독 URL은 발화에서 분리합니다.
- 대본/장면/표현을 함께 선택하고 목표·설명 직접 수정, 장면 합치기, 같은 원본 재사용 이유 기록.
- 장면 방향 선택/잠금과 원문 리비전, 변경 전후·영향 장면 확인. 오래된 창의 저장은 409로 거부합니다.
- 현재 EP001 36컷을 명세 해시에 결속한 작업 사본으로 가져오기. production 파일을 변경하지 않습니다.
- PNG/JPG/WebP, MP4/WebM, TXT/JSON 원본 등록과 decode/hash/출처 기록. 의미·권리 검토는 pending입니다. 영상 검증은 시스템 ffprobe를 사용합니다.
- 로컬 아카이브 후보의 검증 후 작업 사본 가져오기, 녹음 등록·재생, 문단별 수동 시간 초안과 작업용 SRT/VTT 내보내기.
- JSON 저장/새 사본 불러오기, CSV, 자료 요구 목록, 비생산 파이프라인 전달안.

Studio 제안기는 **로컬 규칙 기반 초안**입니다. 별도의 [AI 분석 코어](AI-ANALYZER-TASK.md)와 [지속 작업/API](AI-ANALYSIS-JOB-TASK.md)는 구조화된 구간별 제안, 명시적 전송·과금 동의, 호출 체크포인트와 인증된 결과 조회를 구현했습니다. [AI 분석 화면](AI-ANALYSIS-UI-TASK.md)도 연결됐습니다. 합성 모델로 큐·취소·복구·변조 거부를 검증했고, 격리된 실제 브라우저에서 결과 조회·대기 작업 취소·대본 변경 후 결과와 동의 초기화를 확인했습니다. 선택한 제안의 기획 반영도 합성 입력과 브라우저에서 검증했으며 실제 모델 품질·과금 검증은 남아 있습니다. 자동 음성 정렬도 미연결입니다. 조건부 자막·최종 출력과 승인된 음악·효과음의 v2 고정 게인 믹싱은 Studio에 연결됐으며, 격리된 합성 입력으로 브라우저 작업 생성·실행·다섯 파일 다운로드와 영상 끝까지 재생을 확인했습니다. 선택형 실시간 자료 탐색·수집은 Studio 화면과 로컬 API에 연결되었으며, 자동 대본 검색이나 제작 승인은 아닙니다. 로컬 아카이브 후보 가져오기, 음성 수집·수동 시간 초안, 렌더 엔진 진단, 조건부 컷 임시 렌더, 조건부 전체 에피소드 시각 임시 렌더와 최종 측정 녹음을 정식 카탈로그에 맞추는 조건부 오디오 조립은 별도 작업입니다. 현재 EP001은 활성 컷 루트·생성 계약·카탈로그가 없어 정식 컷·전체 에피소드·오디오 조립이 차단됩니다. ‘같은 의미’와 ‘쉬운 제작’은 사람 검토 전 가설입니다. 장면 방향 잠금은 자료·스타일·컷 PASS가 아닙니다.

## AI 연결 준비

Studio의 ‘AI 모델 연결 준비’는 이제 API 키 대신 Codex CLI 실행 파일과 활성화·모델 형식을 확인합니다. 서버 컴퓨터에서 CLI에 로그인하고 `VISUALMAKER_AI_ENABLED=1`로 활성화한 뒤 서버를 재시작하세요. 실행 파일 경로와 모델 지정은 선택 사항입니다. 준비 상태 조회는 모델을 호출하지 않으며 로그인·응답 품질을 검증하지 않습니다. 실제 분석에는 대본 외부 전송·계정 사용량에 대한 별도 동의가 필요합니다. 설정과 실행 제한은 [Codex CLI 연결](AI-CLI-TASK.md), 전환 전 기록은 [과거 API 연결](AI-CONNECTION-TASK.md)을 참고하세요. 전체 기능의 코드 구현율 추정치는 약 60%이며 실제 제작 완료율이 아닙니다.

## 보관과 복원 방법

`data/visualmaker/studio.sqlite`에 프로젝트와 변경 리비전을 저장하고 `assets/`에 원본을 SHA-256 파일명으로, `receipts/`에 파일별 검증 기록을 보관합니다. `VISUALMAKER_DATA_DIR`로 별도 테스트/저장 위치를 설정할 수 있습니다. 서버를 정지한 뒤 **data/visualmaker 폴더 전체**를 복사해 백업하세요. JSON 내보내기는 미디어 파일과 검증 기록을 포함하지 않으며, 자료가 있는 계획을 복원하려면 해당 원본과 검증 기록이 모두 같은 자료 폴더에 있어야 합니다. 누락/변조 파일은 조회·import·export 검증에서 거부합니다.

등록한 자료는 다른 호환 자료 요구에 연결해 재사용할 수 있습니다. 연결 해제는 자료 파일·등록 영수증을 삭제하지 않습니다. Studio의 출처·사용 조건·의미 대응은 각각 근거를 적어 남기는 **작업용 관찰**입니다. 기록은 자료 바이트 SHA-256과 해당 요구를 공유하는 장면의 내레이션·의도·선택 방향에 묶입니다. 자료 배정이나 장면 의미가 바뀌면 해당 기록은 과거 이력으로 남고 현재 판단은 다시 대기로 표시됩니다. JSON 사본 불러오기는 관찰 기록을 초기화하며, 원본/영수증은 별도로 계속 필요합니다. 세 항목을 모두 기록해도 제작 자료 승인·권리 허가·컷 PASS·영상 렌더 권한이 생기지 않습니다.

`format=handoff` 전달안에는 읽기 전용 `adoptionReview`가 포함됩니다. 고정된 현재 EP001 명세와 제작 상태의 바이트 해시를 기록하고, Studio 장면의 명시적 원본 컷 ID만 대조합니다. 대본·의도·선택 방향의 전후 차이, 합치기·순서 변경·누락·중복과 자료 검토 관찰을 보여줍니다. 출처 해시가 바뀌거나 파일이 없거나 잘못된 경우에는 막힌 제안으로 표시합니다. 제작 상태는 파일에 선언된 현재 값의 요약이며 validator 통과 판정이 아닙니다. 이 보고서는 episode-spec 변경 파일이나 렌더 작업을 만들지 않으며 `productionAuthority=false`, `renderEligible=false`입니다. 편집자는 차이를 검토한 뒤 단일 episode-spec 권위를 수동 수정하고 정식 생성기·검증기·별도 자료/스타일/컷 검토를 거쳐야 합니다. 이 전달안 자체는 렌더 작업을 시작하지 않습니다.

### 녹음 음성 수집 API

로컬 인증이 필요한 `POST /api/studio/narration`은 multipart의 `id`, `baseRevision`, `scriptSha256`, `file`을 받습니다. 전체 요청은 40.1MB, 파일은 40MB로 제한합니다. 파일명·브라우저 MIME과 무관하게 WAV/MP3/M4A 바이트를 검사하고 시스템 `ffprobe`로 실제 음성 스트림과 양수 길이를 측정합니다. 성공 응답은 `{plan, take, currentScriptMatch:true}`이며 Plan의 선택적 `narrationTakes`에 해시·측정 길이·수집 당시 대본 해시와 리비전을 남깁니다. 프로젝트를 수정해도 대본 해시가 같으면 녹음이 현재 상태이고, 대본이 바뀌면 기록은 이력으로 남습니다. JSON 사본 불러오기는 녹음 기록을 초기화합니다.

`GET /api/studio/narration/media?id=…&takeId=…`는 같은 인증 헤더로 녹음을 읽고 단일 바이트 범위 요청을 지원합니다. 녹음 바이트는 `narration/`, 검증 기록은 `narration-receipts/`에 있으므로 SQLite만이 아니라 전체 자료 폴더를 함께 백업해야 합니다. Studio의 `녹음 음성`에서 파일을 등록하면 측정 길이와 현재 대본 일치 여부가 기록되고, `녹음 듣기`로 인증된 파일을 재생할 수 있습니다. 이 API는 수집과 측정만 제공하며 최종 음성 잠금·자동 정렬·영상 타이밍 수정·제작 승인을 하지 않습니다.

### 내레이션 시간 초안 API

`GET /api/studio/narration/timing?id=…&takeId=…`는 녹음·대본 해시와 저장된 시간 초안 이력을 돌려줍니다. 현재 대본에 맞는 저장본이 없으면 각 발화 문단의 공백 제외 Unicode 글자 수에 비례하여 녹음 길이를 나눈 미저장 `text-weighted-estimate`를 제공합니다. 이는 실제 발화를 관찰·정렬한 시간이 아닙니다. `POST`는 `{id,baseRevision,takeId,scriptSha256,audioSha256,segments:[{segmentId,startSeconds,endSeconds}],manualReviewConfirmed:true}`를 받아 문단 순서와 텍스트, 오디오 길이, 겹침 여부 및 사용자의 명시적 수동 확인을 검사한 뒤 새 `manual-timing-draft`를 Plan 리비전에 추가합니다. 이전 초안은 덮어쓰지 않고 이력으로 남습니다. 같은 인증을 거친 `GET`에 `format=json&timingId=…`를 붙이면 저장된 초안만 JSON으로 내보냅니다. `format=srt|vtt&baseRevision=…&timingId=…`는 현재 대본·녹음과 일치하고 명시적으로 수동 확인된 저장본만 작업용 문단 자막으로 내보냅니다. 예전 미확인 저장본은 JSON 이력으로 남지만 SRT/VTT는 받을 수 없습니다. 대본을 바꾸면 이전 시간 초안은 새로운 대본에 자동 적용되지 않습니다. 이 초안은 컷 타이밍·자막 승인·최종 음성 잠금·제작 승인이 아닙니다.

SRT/VTT 본문은 대본의 발화 문단 원문을 사용하지만 리터럴 `<`, `>`, `&`는 텍스트로 보이도록 이스케이프합니다. CRLF는 LF로 정규화하며, 큐 구분을 깨는 빈 줄과 지원하지 않는 제어 문자가 있는 문단은 내보내기를 거부합니다. 응답 크기는 UTF-8 기준 1MB 이하입니다. 이 경우 원문을 자동 수정하지 않고 JSON 이력으로 확인할 수 있습니다.

Studio 하단의 **제작 변경안 검토**를 누르면 현재 프로젝트·리비전의 전달안을 다시 읽어 장면별 전후 차이와 자료 관찰을 화면에서 볼 수 있습니다. 다른 프로젝트나 리비전으로 바꾸면 이전 화면은 닫힙니다. 오류가 나면 같은 위치에서 재시도할 수 있습니다. 기존 **파이프라인 전달안**은 검토 당시의 JSON 파일을 내려받는 기능이며, 화면은 열 때마다 현재 원본 해시를 새로 조회합니다. 화면에서 제작 명세를 수정하거나 승인하지 않습니다.

### YouTube 참조 연구 코어 (초안)

`visualmaker-reference-study-v1`은 사용자가 제공한 YouTube 영상의 화면 구성·모션·편집을 구간별로 기록하고, 재현 작업 중 VisualMaker에서 부족한 기능을 별도 **도구 공백 → 기능 개선 제안**으로 정리하는 순수 데이터 코어입니다. 관찰에는 구간 시간, 로컬 프레임 선언과 SHA-256, 화면 문법 9개 항목이 들어갑니다. 각 항목은 근거 프레임에 연결한 관찰 메모 또는 이유를 적은 `unknown`/`not-applicable`이어야 합니다. 모션·홀드 주장은 서로 다른 두 시점의 프레임 근거가 필요합니다. 선언 경로는 상대 POSIX 경로만 허용하고 NUL, 절대 경로, Windows 드라이브·UNC, 역슬래시 및 traversal을 거부합니다.

원본에서 가져올 요소, 가져오지 않을 요소, 우리 소재로 대체할 의도는 각각 따로 적습니다. 기능 개선 제안은 특정 관찰을 바꾸지 않고, 필요한 VisualMaker 동작·현재 한계·근거 또는 미확인 사유·검증 가능한 완료 기준을 기록합니다. `observed` 공백에는 해당 관찰의 원본 프레임 ID, 재현/프로브 산출물의 종류·미디어 타입·경로·선언 SHA-256·시점, 짝지은 비교 시점과 비교 메모가 필요합니다. 다른 관찰의 프레임을 섞거나 원본 프레임만 제시할 수 없습니다. 비교 전 가설은 `hypothesis`와 미확인 사유로 남깁니다. 선언 SHA-256은 실제 파일 존재나 바이트 검증을 뜻하지 않습니다. 원본 영상 문법의 변경이나 임의 개선으로 해석되지 않습니다.

현재 코어는 URL을 검사하고 canonical YouTube 링크만 저장합니다. 영상에 접속하거나 프레임을 추출·분석하지 않으며, 로컬 파일의 실제 존재·바이트 해시도 확인하지 않습니다. 따라서 빈 초안은 생성할 수 있지만 분석은 차단 상태입니다. 구조 검증 성공도 사람의 참조 검수, 참조 충실도 PASS, 스타일 프레임 검토 자격, 컷 PASS 또는 제작 권한을 부여하지 않습니다. 자동 분석·원격 접속·렌더링·제작 권한은 모두 `false`입니다. 현재는 화면이나 저장 기능에 연결하지 않은 코어이며 다음 작업은 이 스키마를 사용하는 별도 참조 작업 공간입니다.

브라우저는 저장 원장이 아닙니다. 새로고침 후 서버 저장본을 다시 읽습니다. 서버가 재시작되어 연결 토큰이 달라지면 작업 화면을 새로고침하세요.

`DESIGN.md`는 제품/UX/데이터/운영 설계, `RESEARCH.md`는 실제 검토 파일과 공식 문서, `BACKLOG.md`는 구현할 PR 단위 작업과 완료 조건이다.

## 참조 검증 실행

Python 3.10 이상에서 실행한다.

```bash
python -m venv .venv
# 가상환경을 활성화한 뒤:
python -m pip install -r requirements.txt
python validate_design.py
python -m unittest discover -s tests -v
```

기본 예시는 미확정 초안이다. `python validate_design.py --publish`는 **실패해야 정상**이다. 발화 대본 승인과 실제/검토된 음성 정렬이 없기 때문이다. 이 옵션은 발행 동작이 아니라 데이터 상태 검사다.

테스트 fixture의 `audio_test`, 0으로 구성된 SHA, 가상 파일 경로 등은 검증 분기를 확인하는 합성 데이터다. 실제 파일을 생성·확보했다는 뜻이 아니다. 참조 검증기는 파일 존재 여부·다운로드·음성·템플릿 화면 구현을 검사하지 않는다.

## 범위와 확인 결과

원본 프로젝트는 GitHub 연결 도구를 통해 정적 검토했다. 컨테이너의 clone 시도가 DNS 오류로 실패했으므로 원본의 설치/빌드/실행 검증은 하지 않았다. 직접 작성한 규격/예시/참조 검증기의 합성 테스트 **23개**는 이 패키지 생성 환경에서 실행해 통과했다. 결과는 `test-results.txt`다.

# 로컬 실행 작업 (visualmaker-job-v1)

## 조건부 최종 출력과 고정 게인 믹싱

`core/finalization.ts`와 `renderer/finalization-engine.ts`는 명세가 선택한 최종 출력 계약, 실제 사용자 검수 마커, 확정 대본·자막 범위, 성공한 오디오 작업의 영상/영수증을 검증합니다. v1은 영상·오디오 스트림을 유지하면서 선택 가능한 MP4 자막 트랙, SRT/VTT, 지정 프레임 PNG와 해시 영수증을 만듭니다. v2 백엔드는 승인된 고정 게인 음악·효과음을 합산해 AAC로 인코딩하되 원본 영상·자막·음성 presentation을 보존합니다. 자막 burn-in, 자동 덕킹·정규화·반복·페이드는 지원하지 않습니다.

내부 코어에 더해 `episode-finalization-export` 작업 대기열·자식 워커와 인증된 준비 상태/요청/다운로드 API가 연결됐습니다. 정확히 다섯 파일을 원자적으로 게시하고, 현재 입력과 작업·시도·리비전 및 파일 해시를 다시 검증합니다. Studio의 최종 내보내기 패널과 작업 제어·파일 다운로드도 연결됐습니다. 사이드카·영수증 받기와 MP4 최초 취득은 전용 인증 API를 거칩니다. MP4는 OPFS 스트리밍으로 처리하며, 취득 후 로컬 사본의 재생·다운로드는 서버 재검증을 하지 않습니다(브라우저 한도 2GB, 클라이언트 영상 SHA 재계산은 아님). 프로젝트/리비전/시도 변경이나 화면 해제 시 진행 중인 요청을 취소하고 소유 임시 파일의 정리를 시도합니다. 후속 격리 HTTP 서버·브라우저 검증에서 새 작업 생성·실행·5개 다운로드와 MP4 끝까지 재생을 확인했습니다. 성공 검증은 합성 승인 입력만 사용했으며 실제 EP001 승인 제작은 미검증입니다. 별도 현재 EP001 명세 미러에서는 36컷·timing-draft와 첫 차단 사유 `post-lock-contract-missing`, 재조회 전후 비활성 내보내기 버튼 및 작업 0건을 확인했습니다. 후속 제작 게이트까지 검증한 것은 아닙니다. 새 오디오 작업의 v2 계약에는 제작 당시 spec/state 바이트를 보관하고, 별도 최종화 조회가 spec 불변과 picture-lock의 네 필드 전환만 검증합니다. 출력 설정은 오디오 제작 전에 spec에 선언한 고정 addendum 경로에서 읽으며, 이후 spec 변경이나 스냅샷 없는 과거 작업의 소급 보정은 허용하지 않습니다. 기존 오디오 다운로드의 엄격한 해시 검증은 유지됩니다. 격리된 합성 승인 입력의 워커/API 경로는 검증했지만 실제 EP001 승인 경로는 미검증입니다. 기술 결과는 `productionAuthority=false`, `reviewApproved=false`이며 사용자 승인이나 실제 제작 완료를 의미하지 않습니다. 범위와 제한은 [브라우저 검증](FINALIZATION-BROWSER-TASK.md), [Studio 카드](FINALIZATION-STUDIO-TASK.md), [작업/API 카드](FINALIZATION-JOB-API-TASK.md), [출력 작업 카드](POST-LOCK-FINALIZATION-TASK.md)와 [전환 작업 카드](POST-LOCK-TRANSITION-TASK.md)를 참고하세요.

고정 게인 믹서 기술 엔진은 48kHz 스테레오 음성에 음악·효과음을 지정 샘플 위치와 음량으로 합산합니다. v2 선택 계약과 별도 사용자 믹스 입력 승인·권리 자료가 정확히 결속된 경우에만 작업 큐를 통해 MP4/AAC와 기존 다섯 파일을 게시합니다. 기술 엔진 한도는 10분이며, 자동 덕킹·정규화·반복·페이드는 지원하지 않습니다. 믹스 입력 승인은 출력 청취·영상 승인과 다르고, 도구는 실제 권리나 사용자 승인 기록을 생성하지 않습니다. 최신 독립 도구 검증은 227/227 통과했으며, 합성 승인 입력에서 v1·v2 실제 워커·다섯 인증 산출물·롤백·재시도·취소를 확인했습니다. 새 합성 프로젝트의 Studio v2 브라우저 검증에서는 최종화 작업이 없는 준비 상태부터 직접 생성·실행하여 v2 기록 표시, 다섯 다운로드와 1920×1080 MP4의 3.633초 끝까지 재생을 확인했습니다. 실제 EP001 적용이나 청취·시각·권리 승인을 뜻하지 않습니다. 실패·취소한 v2 staging은 안전을 위해 보존하며, 직계 작업 폴더 수 4개와 여유 공간 검사로 새 v2 작업을 제한합니다. 임의 외부 파일 교체나 원자적 파일시스템 경쟁까지 보호하는 기능은 아닙니다. v2 자막의 `<`, `>`, `&`, 중괄호·역슬래시는 현재 명시적으로 차단합니다. 구현·검증 범위는 [기술 믹서](FIXED-GAIN-MIX-TASK.md), [v2 연결 카드](FINALIZATION-MIX-V2-TASK.md), [UI 카드](FINALIZATION-MIX-V2-UI-TASK.md)와 [v2 브라우저 검증](FINALIZATION-MIX-V2-BROWSER-TASK.md)을 참고하세요.

Studio의 “현재 리비전 패키지 만들기”는 SQLite에 검증된 계획 스냅샷과 SHA-256을 저장합니다. 대기 작업을 실행하면 `data/visualmaker/jobs/` 아래에 계획 JSON, 장면 CSV, 자료 요구 JSON, 패키지 명세를 기록합니다. 완료 상태의 파일만 API에서 해시를 다시 확인해 내려받을 수 있습니다. 대본이나 장면을 고쳐도 이전 작업의 스냅샷은 바뀌지 않으며 화면에 리비전 차이가 표시됩니다.

선택형 자료 API는 인증된 `/api/studio/source-search`와 `/api/studio/source-acquire`입니다. 현재 프로젝트의 비어 있는 이미지/영상 요구에 사용자가 직접 검색어와 Wikimedia Commons·NASA·미국 의회도서관(LOC) 중 제공처를 지정합니다. 검색은 메타데이터만 보여주고, 선택 수집은 제공처 메타데이터를 재확인한 뒤 정확히 한 파일을 기존 업로드 검증에 넣습니다. NASA/LOC는 이 연결에서 이미지만 지원하고 LOC가 접근을 거부하면 오류를 표시합니다. 수집 파일은 원본 여부와 권리 상태를 명시해 `pending-review`로 남으며 제작 파일이나 승인을 바꾸지 않습니다. Studio의 자료 요구 화면에서 검색·후보 선택·선택 파일 수집을 사용할 수 있으며 출처·권리·의미 검토는 대기 상태입니다.

일반 작업 상태는 `queued → running → succeeded/failed/cancelled`이며, 실패·취소 작업은 같은 스냅샷으로 재시도합니다. AI 분석은 예외로 모든 재시도가 금지됩니다. 외부 호출 시작 뒤 불확실한 결과는 `needs-review`로 남으며, 제공자 처리·청구를 확인한 뒤 새 동의와 새 요청 키로 별도 요청해야 합니다. 같은 요청 키와 입력은 이후 프로젝트가 수정되어도 기존 작업을 돌려줍니다. Studio의 실행 요청은 별도 로컬 Node 프로세스를 시작하고 202를 반환합니다. 대기 작업의 실제 상태와 결과는 화면의 주기적 조회로 확인합니다. SQLite가 작업 대기열의 원장이며 여러 worker가 동시에 실행돼도 한 시도만 작업을 선점합니다.

Studio 서버 밖에서 대기 중인 작업을 처리하려면 저장소 루트에서 `pnpm run visualmaker:worker`를 실행하세요. 이 명령은 현재 `VISUALMAKER_DATA_DIR`의 대기열을 한 번 끝까지 비우고 종료합니다. Studio 서버와 다른 자료 폴더를 지정하면 서로 다른 대기열을 사용하므로 동일한 환경 변수 값을 설정해야 합니다. 이 명령은 상주 서비스가 아니며 새 작업이 생길 때 자동으로 다시 실행되지 않습니다. 서버가 종료돼도 이미 시작된 로컬 worker는 독립적으로 계속 실행될 수 있습니다. worker가 중단된 실행 작업은 5분 임대가 만료된 뒤 명시적으로 중단 복구하고, 일반 작업만 실패 상태에서 재시도하세요. AI 분석은 복구 후에도 재시도할 수 없으며 외부 호출 시작 이후에는 `needs-review`로 남습니다. 만료 전 활성 작업은 복구할 수 없습니다. 일반 작업의 재시도는 저장된 원본 스냅샷을 유지하며, 등록 자료의 로컬 파일이나 검증 기록이 바뀌었다면 실행에 실패합니다. 작업 실행에 사용된 임대 토큰은 API에 공개되지 않습니다.

`render-preview` 요청은 `blocked`로 저장됩니다. 이 계획 미리보기 종류와 별개로 Remotion/FFmpeg 진단·조건부 정식 컷·전체 시각 임시본·오디오 조립 작업이 있습니다. 자료·권리 승인과 생산 권한 승격은 자동으로 수행하지 않습니다. 패키지의 `productionAuthority`는 항상 `false`이고 업로드 자료는 `pending-review`입니다.

## 조건부 최종 녹음 조립

Studio의 `최종 녹음 시간에 맞춘 영상 조립`은 현재 제작 입력·최종 녹음·컷 QC 게이트를 조회하고, 충족된 경우에만 `audio-timed-assembly` 작업을 요청합니다. 등록된 EpisodeTimeline 전체 렌더에 정확히 결속된 최종 녹음을 실제 디코드한 샘플 길이와 프리롤로 배치합니다. 결과는 `provisional-voiced-episode.mp4`와 해시·측정 영수증이며 제작 승인이나 최종 출력이 아닙니다. 브라우저 재생·다운로드는 최대 2GB, 백엔드 출력 한도는 4GB입니다.

실제 합성 입력으로 렌더·음성 배치 및 하위 게시·파일 검증 경로를 테스트하지만 현재 EP001의 승인 입력을 갖춘 전체 성공 경로는 미검증입니다. 시험용 SQLite 계약은 실제 제작 게이트 통과 증거가 아니며 인증된 제작 API는 이를 거부합니다. 자세한 범위와 검증 한계는 [오디오 조립 작업 기록](AUDIO-TIMED-ASSEMBLY-TASK.md)을 확인하세요.

## 미리보기 준비 상태 조회

Studio의 `미리보기 준비 상태 확인`은 현재 계획 리비전의 선택된 표현과 자료 요구만 읽어 장면별 차단 사유를 표시합니다. 배정된 원본 수와 조회 순간 로컬 바이트를 확인한 원본 수는 각각 고유 SHA-256으로 셉니다. 출처·사용 조건·의미 대응 기록은 작업용 관찰이며 제작 승인이 아닙니다. 녹음 파일이나 수동 타이밍이 없어도 이 조회는 가능합니다.

`GET /api/studio/preview-readiness?id=PLAN_ID&baseRevision=N`은 기존 로컬 세션 헤더를 요구하고 프로젝트·리비전이 바뀌면 409를 반환합니다. 파일 경로나 세션 토큰을 URL에 넣지 않습니다. 조회는 계획, 작업, 제작 데이터를 바꾸지 않습니다. 모든 장면에는 렌더러 미구현과 제작 계약 미결속이 남고 `productionAuthority`, `renderEligible`, `previewExists`, `eligibleForCutReview`는 계속 `false`입니다.
# 렌더 엔진 점검

`renderer-diagnostic`은 현재 리비전의 작업 기록에 결속된 별도 기술 자가검사입니다. 고정 640×360·30fps·60프레임 Remotion 패턴을 실제 렌더링하고 FFprobe/FFmpeg로 코덱·길이·처음/마지막 프레임 변화를 측정합니다. 인증된 `diagnostic.mp4`와 `diagnostic.json`만 제공하며 제작 컷, 참조 문법, 스타일, playable parity 또는 제작 승인을 뜻하지 않습니다. 기존 `render-preview`는 여전히 차단됩니다. 로컬 Remotion 의존성, 캐시된 headless browser, FFmpeg/FFprobe가 없으면 설치나 다운로드를 시도하지 않고 실패합니다.

## 정식 카탈로그 컷 임시 렌더

`canonical-cut-preview`는 별도 종류의 작업입니다. 현재 EP001의 episode-spec에 정확히 결속된 Studio 장면만 검토하고, manifest-contracts → 활성 컷 → render-catalog → `production-index`의 검증기가 모두 통과한 경우에만 정식 컷 composition 전체 길이를 Remotion 자식 프로세스에서 렌더하도록 연결했습니다. 컷과 실제 교차하는 경계에 필요한 인접 컷만 포함한 원본 바이트 폐포를 작업 전용 public 디렉터리에 복사합니다. 호출자는 경로·코드·props·출력 규격을 지정할 수 없습니다. 계약과 원본 해시는 대기, 실행, 게시, 재생 시 다시 검증합니다. 결과는 `provisional-cut.mp4/json`이며 제작 권한·스타일·컷·playable parity 승인을 부여하지 않습니다.

현재 EP001의 활성 컷 루트와 생성 계약/카탈로그는 아직 없어 이 작업은 구조화된 `blocked`로만 저장됩니다. 이 상태를 통과시키는 예시 자산이나 승인 표시는 만들지 않았으며, 실제 정식 컷 MP4 성공 경로는 독립 실행 검증 전까지 확인되지 않았습니다. Studio의 렌더 엔진 점검은 여전히 별도 고정 패턴이고, 역사적 `render-preview` 종류도 계속 차단됩니다.

## 에피소드 타임라인 점검

Studio는 현재 EP001 컷 순서와 임시 프레임 창을 확인할 수 있는 타임라인을 보여준다. 인증된 JSON 내보내기는 점검 정보만 담는다. 수동 녹음 문단 시간은 별도 초안 구간이며, 컷과 음성의 동기화 또는 제작 승인을 뜻하지 않는다. 현재 EP001은 활성 컷 루트가 없어서 모든 컷 영상이 미제공 상태다. 이 메타데이터 조회는 저장된 영상이나 영수증을 읽지 않으며, 실제 영상 검증은 작업 패널의 별도 인증 경로에서 수행한다.

## 전체 에피소드 임시 영상

### 격리된 정식 경로 기술 검증

새 통합 테스트는 정상 계획 가져오기 → 무음 프리뷰 작업 큐/워커 → 음성 합성 작업 큐/워커 → 허용된 picture-state 전환 → 최종화 평가 → 실제 MP4/SRT/VTT/PNG/receipt 내보내기를 검증한다. 독립 실행과 검수에서 1컷·109프레임·1920×1080·30fps 합성 자료가 통과했으며, 입력 변경 6건은 거부됐다. 구현 중 발견한 소스 선정 단계, 런타임 승인 해시, 과거 검수 장부, 활성 버전 폴더 식별자 계약 충돌도 수정했다. 자세한 범위와 실행 근거는 `CANONICAL-EXPORT-FIXTURE-TASK.md`에 기록한다.

후속 격리 검증에서는 실제 인증 핸들러의 요청 → 최종화 작업 큐 → 별도 워커 → FFmpeg → 다섯 파일 게시·다운로드까지 연결했다. 임대 만료 복구, 게시 실패 롤백·재시도, 자식 실행 후 취소, 범위 요청 및 입력/출력 변조 거부도 검사했다. 이 핸들러 검증과 별도로 v1 및 v2 Studio의 합성 입력 HTTP·브라우저 성공 흐름을 확인했다. `productionAuthority=false`, `reviewApproved=false`를 유지하며 실제 EP001의 인간·권리 승인이나 제작 완료를 뜻하지 않는다. 실제 EP001은 기존 차단 상태로 남는다.

Studio의 `전체 에피소드 임시 영상 작업 만들기`는 현재 제작 명세와 필수 검토가 통과한 경우에만 고정된 EpisodeTimeline 전체를 무음 MP4로 렌더하도록 요청한다. 현재 EP001은 활성 컷 루트와 생성 카탈로그가 없어 작업 목록에 차단 사유가 표시된다. 성공 작업의 영수증은 프로젝트·리비전·시도·SHA-256에 결속해 확인한다. OPFS를 지원하는 브라우저에서는 인증된 응답을 브라우저 전용 임시 파일(최대 2GB)로 스트리밍한 뒤 재생·다운로드할 수 있다. 사용자 기존 파일은 선택하거나 덮어쓰지 않는다. 정상 취소와 화면 해제 시 자신이 만든 임시 파일을 정리하지만 갑작스러운 브라우저 종료 후 삭제까지 보장하지는 않는다. 전체 파일을 브라우저 메모리에 올리지 않으며 서버가 전송 전 해시를 검증하고 화면은 전달 바이트 수를 확인한다. 저장된 파일의 클라이언트 SHA-256 재계산이나 전체 EP001 성공·승인은 주장하지 않는다.
