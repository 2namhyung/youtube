This is part of completing the tool, not a new production approval route.

## API/data contract

- Readiness: authenticated no-store `GET /api/studio/finalization?projectId&baseRevision`, envelope `readiness` with schema/scope/composition/validators/blockers/renderEligible and false authority/review flags. Public DTO intentionally omits execution contract, binding and private paths. Validate against actual current plan/snapshot hash, fail closed on malformed/scope drift; do not expect the older audio response envelope or headers absent from this endpoint.
- Enqueue: jobs POST `action=enqueue,kind=episode-finalization-export,projectId,baseRevision,idempotencyKey` only. Validate public job + public readiness, never require raw execution contract. Retry uncertain POSTs with same key within the same mounted scope; reset scope using plan/revision/token keyed mount. Cancel in-flight requests on scope change/unmount; stale response must not set state or expose downloads. Disable duplicate enqueue while queued/running; refreshing readiness cannot revoke a stored job.
- Controls: reuse existing run/cancel/retry/recover UI; do not auto-approve or auto-run. Clearly label finalization exports as technical outputs, not production/human PASS. Retain current revision warnings, stale attempt checks and sanitized errors.
- Downloads: dedicated `jobs/export-media` endpoint with jobId/projectId/baseRevision/attempt/name; allow only export.mp4/export.srt/export.vtt/export.png/export.json. Never route these through old generic download endpoint. Validate response scope/no-store/MIME/false authority; verify bounded receipt bytes/hash and job-bound receipt fields and all five artifact records. Use stream-to-OPFS pattern for large MP4 with 2GB browser cap; bounded sidecars/PNG receipt, abort and exact owned temporary file cleanup. Do not buffer large video. No authenticated token in URLs. Avoid displaying private paths or offering stale job outputs.
- Receipt schema `visualmaker-finalization-job-receipt-v1`: source audio scope/hashes, four media output hashes and technical evidence, with fifth receipt hash in job artifact record (no self-reference). Read actual backend types/source to implement exact validator. Server revalidates canonical inputs and all five files; UI validation must not claim client MP4 hash recomputation if only byte count is checked.
