# Finalization job and authenticated API

## Story / architecture / ownership

User story: Studio checks finalization readiness for its current project/revision, enqueues a canonical export, runs/cancels/retries through the existing local worker, and obtains verified MP4/SRT/VTT/PNG/receipt downloads. This task implements the durable job and authenticated API boundaries first; Studio integration follows, not a substitute for the whole-tool goal. Existing local Next.js handlers, SQLite lease/attempt machinery and child process execution are retained. No deployment, cloud queue, provider/network call or new dependencies.

Root owns this task card and documentation/package registration. One backend writer owns `visualmaker/core/jobs.ts`, `core/dispatch.ts`, narrowly necessary `core/finalization.ts` exports, `visualmaker/worker.ts`, finalization renderer contract plus new finalization runner, existing `src/app/api/studio/jobs/route.ts`, new `src/app/api/studio/finalization/route.ts` and `jobs/export-media/route.ts`, and new focused job/API tests. Existing finalization engine may receive only necessary job/attempt receipt bindings, with explicit explanation. No redelegation; preserve unrelated edits. Do not modify UI, shared canonical fixture helpers, episode authorities/state/generated/active manifests/approvals/raw/wiki/user data, environment/dependencies or Git. Synthetic test data is permitted only in owned bounded Temp roots.

## Data / API contract

- Job kind `episode-finalization-export` uses current project ID, baseRevision and idempotencyKey only. Caller cannot provide source job, paths, captions, approval flags, CLI/props/mix or output names. The canonical spec/addendum and actual succeeded source audio job remain sole inputs.
- Persist a versioned immutable finalization execution report and SHA, bounded serialized size, exact plan snapshot/revision and actual source job/attempt/receipt/MP4 hashes. Blocked readiness creates a truthful blocked job, never a fake success or approval. Revalidate current canonical eligibility, plan revision and all inputs before claim/execution, after child execution, before atomic publication and before downloads. Never replace strict old audio readers with the archival reader outside its specified finalization purpose.
- Use existing lease token, heartbeat, expiry recovery, attempt and cancellation semantics. Child runner executes the existing FFmpeg engine in an exact job-owned staging root with sanitized environment, timeout and cancellation. No in-process fake result, succeeded SQLite seed or caller-controlled validation callback in production.
- Publish exactly the five allowlisted exports atomically. Receipt binds export job/attempt/project/revision/snapshot/execution SHA to actual source audio job/attempt/receipt/artifact and the four other output hashes. The fifth artifact is the receipt itself: its exact byte SHA and size are bound by its database artifact record, never by a self-referential receipt field. Check all output bytes and shape before success; missing/extra/tampered outputs cannot publish. Engine packet/frame/thumbnail/caption integrity checks remain mandatory. Outputs retain productionAuthority=false/reviewApproved=false.
- `GET /api/studio/finalization?projectId=...&baseRevision=...` is guarded, bounded and no-store, reports canonical blockers and readiness without mutating editorial authority. Do not expose private absolute data paths, lease tokens or snapshot byte blobs in the public readiness DTO.
- Existing jobs POST supports enqueue/run/cancel/retry/recover with strict accepted keys. Finalization enqueue and readiness responses use public DTOs, not raw execution contracts; job responses, errors and logs must not expose private absolute paths, snapshot blobs or lease tokens. `GET /api/studio/jobs/export-media?jobId=...&projectId=...&baseRevision=...&attempt=...&name=...` is guarded and scope-bound. Five fixed names only; never accept a path. Verify exact succeeded attempt, contract and receipt plus files using bounded streaming hashes/verified FD before response. MP4 supports bounded Range with existing full/range/cancel-safe FD semantics; sidecars/PNG/receipt have correct MIME, no-store, nosniff and fixed attachment names. No completed output is exposed from cancelled/failed/stale inputs.
