## API/data contract

- Continue immutable timing history, exact script Unicode offsets/text/segment IDs, take/audio SHA, transactional baseRevision. No scene/cut duration changes. Locked scene direction is not narration-draft authority; preserve scenes unchanged.
- Saving a new timing draft must require explicit `manualReviewConfirmed:true` from the UI after the user checks the displayed ranges against audio. Persist a server timestamp and true flag as draft workflow evidence only. Existing timing records lacking these fields remain readable/exportable as historical JSON; never infer review or retroactively mark them confirmed. New field pair must be strictly validated in Plan imports and client responses (boolean true + valid timestamp, both present or both absent). Imported project takes/timings still follow existing stripping rules.
- UI checkbox clearly says manually checked ranges, not final voice or subtitle approval. Reset confirmation on any range edit, selected take/project/script/saved-timing scope change and revision refresh. Save disabled unless checked and valid; errors keep input where safe. Global busy and late response guards preserved.
- Extend authenticated GET `/api/studio/narration/timing` with `format=srt|vtt` using id/baseRevision/takeId/timingId. Only a persisted manually confirmed current draft, bound to exact current script+take bytes, may export. Missing timing 404; stale revision/script/audio/segment binding 409; legacy unconfirmed draft 409 with actionable text. JSON historical export remains compatible. Never export estimate or silently choose latest record when ID missing.
- Pure deterministic serializer: one cue per current saved narration paragraph, no inferred word timing. Millisecond rounding, positive finite range, full ordered coverage, in-audio duration and no overlap rechecked after rounding. Collapsed sub-ms ranges fail. Hours >=2 digits, correct comma SRT/dot VTT; indexed SRT and WEBVTT header. Plaintext handling must prevent source text from becoming subtitle markup/control delimiters: encode &, <, > appropriately; normalize CRLF to LF, reject unsupported control/blank-line delimiter if exact safe serialization impossible instead of silently dropping text. Do not insert title, URL, JSON flags or confirmation text as caption cues. Explicitly document literal-text behavior/limits and test hostile `<b>`, `-->`, ampersands, Unicode/Korean and embedded newline. Never change script text to make export pass.
- Response Content-Type appropriate UTF-8, Content-Disposition safe server filename containing `subtitle-draft` and fixed format extension, Cache-Control no-store. Scoped headers identify schema/project/revision/take/timing/script/audio/productionAuthority false. Client validates headers and expected scope before Blob download; response type/body bounds and format integrity must be checked, don't adopt/download a cross-project or late response. No remote fetch/no exposing server paths.
- Preview/UI history presents separate JSON, SRT, VTT buttons and clearly labels provisional manual timing draft. Stale/unconfirmed records explain why SRT/VTT disabled. No automatic ASR/semantic/final/cut PASS claims.
