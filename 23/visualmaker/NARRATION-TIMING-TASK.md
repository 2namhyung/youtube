# Narration timing draft — tool completion slice

## Purpose, boundaries, ownership

Provide an actual Studio workflow: select a measured recording -> see provisional narration-segment time ranges -> listen/edit start/end seconds -> save an immutable timing draft -> reload/history/export. This is NOT ASR, forced alignment, measured word timing, final voice lock, episode retiming, subtitle approval or production authorization. Initial proportional times are explicitly text-weighted estimates, not observations of speech. Studio and all records keep productionAuthority=false; existing scenes/timing/locks stay byte-equivalent except normal plan revision metadata.

Exactly one product writer at a time. Backend writer owns new timing core/API/tests, model/director/store integration, focused test script and current README/IMPLEMENTATION addendum. UI writer later owns timing UI/client/tests, narration panel integration and scoped CSS. Preserve all existing dirty edits; no redelegation/dependency installation/commit/push. Forbidden writes: raw/wiki/video/generated/episode spec or state/approval markers/other worktrees/user projects. Only new isolated temp TEST fixtures are allowed.

## Contract

- Optional append-only Plan.narrationTimings with immutable timing IDs, project ID, capturedRevision, take ID/audio SHA, script SHA, timestamp, method=manual-timing-draft, reviewStatus=draft, productionAuthority=false. Bind an ordered snapshot of narration segments (id, Unicode offsets, exact text) and their proposed startSeconds/endSeconds. Historical records remain parseable after script edits and visible as stale. Old plans with field absent remain supported. Import-copy drops takes AND timing records before schema validation; imported JSON is not an audio backup.
- Creation only against current measured take bound to current script; exact current narration segment coverage/order required. Save under BEGIN IMMEDIATE with current baseRevision, script hash, take hash and existing byte/receipt verification, append immutable record and revisions atomically. No replacement of existing timing record. Only known fields accepted, injected approval/status/method/extra record keys rejected. Reject duplicate/missing/non-narration IDs, changed text, non-number/non-finite values, zero/negative/reversed/out-of-duration ranges and overlaps. Gaps and leading/trailing silence are allowed. Precision/documented tolerance must never hide substantive overlap. Historical validation binds offsets/text against current or history raw script and take identity; never invent historical currentness.
- GET /api/studio/narration/timing?id=...&takeId=... uses existing guard; returns current plan bindings, current matching saved record/history and clearly labelled text-weighted estimated unsaved ranges when no current record. Every narration segment covered once; full duration distributes by non-whitespace Unicode code-point text length, last end exactly duration; empty/no-narration case actionable error. Hash tamper/missing file blocks retrieval/save. POST same route with id/baseRevision/takeId/scriptSha256/audioSha256/segments (exact segmentId/startSeconds/endSeconds) -> 201 {plan,timing}; malformed 400, stale input 409, no token 403. Use bounded existing JSON helper, no client paths/provider calls.
- UI shows selected recording, measured total length, explicit estimation/manual-draft caveat, narration text per row and accessible numeric start/end controls; save/error/loading/history; audio listening via existing authenticated blob flow, a selected row can seek/play its interval and stop at interval end. Native media capability does not mean word alignment. Export saved timing draft JSON only via authenticated API, no new production target.
- Late project/revision/script/take/epoch responses cannot overwrite current plan/editor; use existing scope checks plus abort on unmount, serialized global busy for saves and reloading. Persisted currentness uses script and audio identity, not unrelated revisions. Stale timing history read-only, changing script does not alter old records. No approval wording or new Plan authority route.
