# 구현 백로그와 완료 판정

> 2026-09-17: 원 설계는 비교 근거로 보존합니다. 현재 구현과 채택/변경/미구현 범위는 [IMPLEMENTATION.md](IMPLEMENTATION.md)가 정본입니다. script2video 포크·고정 6종 템플릿·캡처 픽셀 활용은 이 저장소에서 채택하지 않았습니다.


원 설계 당시 상태: 설계·규격·참조 검증기만 제공. 아래 이슈는 당시 제안한 작업이며 현재 완료 표시가 아니다. 현재 구현과 남은 작업은 위 IMPLEMENTATION.md를 따른다. 종속성은 순서이지 일정 추정이 아니다.

## PR 0 — 기준선 보존, 별도 Studio 진입점

기준은 script2video `63ea5ddeba233e35efaadaf0d36c81d8788eabd2`다. MIT 고지 유지와 UPSTREAM 기록을 추가한다. 원본 lockfile을 보존하고 설치·타입 검사·빌드를 실제 개발 환경에서 실행한다. 취약점과 라이브러리 호환성을 검토한 뒤 변경한다. 패키지 이름만 보고 안전하다고 판단하지 않는다.

변경 후보: `app/studio/page.tsx`, `components/studio/*`, `UPSTREAM.md`, 테스트 설정. `components/ChatWorkspace.tsx`의 전체 UI를 복잡하게 늘리지 말고 새 작업 화면을 둔다. 기존 경로는 legacy 기능으로 유지한다.

완료 조건: 모의 데이터만으로 새 화면 로딩, 기존 화면과 충돌 없음, 핵심 의존성/라이선스 기록, 키 없는 실행 안내, 빌드 결과 기록. 원본 앱의 빌드 실패를 새 기능 실패와 분리한다.

## PR 1 — 원문 리비전과 도메인 규격

신설: `lib/domain/script.ts`, `scene.ts`, `asset.ts`, `evidence.ts`, `revision.ts`; JSON Schema 또는 Zod와 TypeScript 타입이 어긋나지 않도록 한 원본 규격에서 생성/검증한다.

원본 `lib/types.ts`는 기존 생성 기능에서 계속 사용하고 새로운 모델을 무리하게 같은 이름으로 대체하지 않는다. 변환이 필요하면 `legacy-shot-adapter.ts`를 명시적으로 둔다.

완료 조건: stable ID와 표시 순서 분리, 대본 수정은 새 revision, 원문 구간 연결, 누락/중복 검출, 설명 역할·확보 방식·레이어·근거 축의 분리. 현재 참조 검증기의 합성 사례를 앱 언어로 포팅한다.

Unicode 주의: 패키지 예시의 source span은 Unicode code point 기준 반열림 `[start,end)`다. JavaScript의 UTF-16 code unit 오프셋과 혼용하지 않는다. 서버가 segment ID를 발급하고 UI 선택 범위를 별도 매핑하거나 code point 변환을 일관되게 적용한다. 줄바꿈 정규화 이전 원본 바이트는 보존하고 정규화 버전의 별도 해시를 쓴다.

의존: PR 0.

## PR 2 — 로컬 영구 저장과 변경 적용

신설: SQLite migrations, ProjectRepository, AssetRepository, RevisionRepository, DecisionRepository. JSON export와 DB 읽기 모델의 경계를 둔다. 대형 파일은 파일 저장소, 메타데이터·해시·상태는 DB에 둔다.

`baseRevision` 확인과 revision 증가를 같은 트랜잭션에서 수행한다. 수정 필드와 잠금 필드를 검사한다. 생성 결과는 run output/candidate로 저장하고 사용자의 확정본으로 자동 승격하지 않는다.

완료 조건: 새로고침/프로세스 재시작 후 복원, 프로젝트별 분리, 잘못된 리비전 409, 확정/잠금 보존, 대본 원본 내보내기, 백업·복원 테스트. IndexedDB 데이터가 지워져도 원장이 사라지지 않음.

의존: PR 1.

## PR 3 — 의미 분석과 표현 대안

신설: `lib/director/analyze.ts`, `propose.ts`, `validate.ts`, `repair.ts`, 모델 capability registry. 공급자 이름/모델 문자열 접두사만으로 이미지 입력 가능 여부를 추정하지 않는다.

입력은 승인 발화 구간, 실제 템플릿 목록, 프로젝트 스타일, 기존 자산 메타데이터, 앞뒤 장면 목표다. 출력은 segment ID를 참조하는 의미 단위와 장면별 두 가지 표현안이다. 후보마다 시작/변화/끝, 요구 자산, 모션 앵커, 대체 표현, 작업 부담의 근거가 있어야 한다.

완료 조건: 모의 제공자와 실제 제공자 한 개를 같은 인터페이스로 교체 가능, 원문을 모델이 임의 수정할 수 없음, JSON 형식 오류가 UI에 투명하게 표시됨, 존재하지 않는 템플릿·자산을 거부, 실패한 구간만 제한 횟수 재생성. 공급자별 한국어 품질은 실제 평가 결과를 별도 남긴다.

유료 모델 호출은 사용자 키/승인된 지출 범위가 있어야 하며 ‘자동검토’ 호출도 비용 원장에 포함한다.

의존: PR 1–2.

## PR 4 — 대본·장면표·후보 검사기

신설: ScriptPane, SceneTable, CandidateInspector, SceneLock, PlanExport. 기본 세 패널 레이아웃과 선택 연동. 지시어만 있는 채팅 창이 아니라 수정 가능한 필드로 제공한다.

완료 조건: 한 장면만 다른 표현으로 바꾸기, 화면 재사용 선택, 불필요한 새 자산 표시, 장면 잠금, 소스 미해결 필터, 대본/화면 설명 직접 편집, JSON/장면표 내보내기. 원문과 대응하지 않는 장면을 저장할 때 원인을 표시한다.

범위 제한: 범용 영상 타임라인, 다중 사용자 동시 편집, 무제한 이미지 생성 제외.

의존: PR 2–3.

## PR 5 — 승인 기반 대본 수정과 영향 분석

신설: ScriptChangeProposal, DiffReview, dependency/invalidation rules. AI는 변경안과 이유를 제시한다. 승인 전에는 현재 대본과 음성을 변경하지 않는다.

완료 조건: 수치/단위/기간/대상/부정어/예외 조건 변화 표시, 채택 시 새 리비전, 영향을 받는 장면 목록, 원문 복원 가능. 색 변경은 음성 캐시를 지우지 않고 대본 변경은 해당 음성/정렬을 stale로 만든다.

의존: PR 2–4.

**P1 완료 판정: 대본→다른 표현 두 개→직접 선택/수정/잠금→확정 가능한 장면표와 미해결 소스 목록까지 앱 안에서 완결.**

## PR 6 — 자산 요구/실제 파일/이용 조건 분리

신설: 파일 업로드·캡처 등록, AssetRequirementResolution, RightsDecision, ProvenanceManifest. ‘원하는 소스 설명’과 ‘실제로 확보한 파일’을 다른 엔티티로 둔다.

완료 조건: 파일 없는 상태를 available로 표시하지 않음, 해시와 실파일 일치, 관련 source/evidence linkage, 사용 조건 보류 상태, 파일 소실 복구 안내, 악성 경로·대형 파일·SVG 처리, 키/개인 메타데이터 노출 방지.

의존: PR 2, 4.

## PR 7 — Pexels 검색 어댑터 하나

신설: 서버 측 검색, 결과 카드, attribution UI, query 단위 캐시, 사용자 선택 후 필요한 파일만 수집. 최신 공식 동영상 경로 `/v1/videos/`와 현재 API 정책을 재확인한다.

완료 조건: 실제 응답 ID 연결, 호출 한도/429 처리, 제공자와 기여자 표기, 파일 URL 만료/재조회, 검색 결과가 없을 때 명시적 빈 상태, 가짜 URL 금지. 외부 AI 분석·대량 임베딩·전체 라이브러리 수집 기능은 기본 비활성화.

의존: PR 6 및 제공자 이용 범위 확인.

## PR 8 — 작업 원장과 예산

신설: 단일 로컬 Node worker, SQLite-backed job queue, heartbeat, lease/fencing, event stream, 승인 예산 원장.

완료 조건: 중복 제출 방지, 재시작 복구, 취소 뒤 늦은 성공 결과의 사용자 데이터 덮어쓰기 차단, 동시 실행 상한, 유료 요청 timeout 후 기존 request ID 조회, 예상/실제 비용 구분, 비용 미확인 시 0원 표시 금지.

합성 타임아웃만 아니라 실제 공급자의 polling/idempotency/cancel 지원 수준도 계약별로 테스트한다. 취소가 이미 발생한 사용량 청구를 되돌린다고 표시하지 않는다.

의존: PR 2–3, P2 유료 자산/음성 기능 전 필수.

## PR 9 — 음성·애니매틱

신설: NarrationTake, waveform/alignment, 장면 스트립, 임시 프레임 컴파일러. 최초는 음성 업로드로도 동작하게 한다. 생성 음성은 선택 사항이다.

완료 조건: 추정/정렬/검토 상태 구분, 한국어 숫자·영문 약어 수동 보정, 컷과 내레이션 독립, 동일한 시계에서 미리보기 재생, 재생 위치 바꾸기/일시정지/다시 시작 시 동기 일관성.

의존: PR 5, 6, 8.

## PR 10 — 템플릿 실제 구현과 렌더 어댑터

신설: 검토한 여섯 템플릿 컴포넌트와 thumbnail/frame/animatic/export API. 이 패키지의 template-registry는 props 규격만 있으므로 실제 컴포넌트 구현이 별도로 필요하다.

완료 조건: 16:9 우선, 9:16은 실제 레이아웃 테스트 이후 추가; 긴 한국어 문장·안전 영역·구도 크롭·레이어 겹침 검증; 같은 props가 미리보기/최종 렌더에 사용됨; 폰트·자산·템플릿 해시 기록; 네트워크가 필요 없는 격리된 렌더.

라이선스 확인: Remotion은 자체 조건, 폰트·아이콘·캐릭터 팩·음성·스톡은 별도 조건. 예시 이미지가 들어 있는 저장소가 곧 그 이미지에 대한 상업 이용 보증은 아니다.

의존: PR 6–9와 엔진 버전/라이선스 결정.

## PR 11 — 내보내기와 운영 검증

계획 JSON/CSV, 선택 자산 manifest, 필요한 촬영/생성 prompt pack, 검토된 타이밍 기반 SRT, 최종 MP4. OTIO는 제한된 컷/미디어 참조만 후속 연결한다.

완료 조건: manifest에서 실제 파일까지 추적, 비밀키 없는 ZIP, 미해결 항목이 있는 초안의 명확한 표시, 최종 렌더의 근거/자산/승인 gate, 프로젝트 복구, 편집기 어댑터별 round-trip 검증. 모션 소스 손실은 사용자에게 알리고 sidecar로 보존한다.

## 배포 전 최소 평가 묶음

10개 주제/상황으로 시작하되 각각 성공뿐 아니라 실패·복구 경로를 포함한다. 비교표, 과정 설명, 사실 데이터, 근거 누락, 희소 소스, 카툰 비유, 긴 한국어 발화, 이전 장면 재사용, 중간 대본 변경, 파일 소실·취소·중복 작업.

평가 기록은 `첫 제안 채택`, `직접 수정 시간`, `수동 소스 검색`, `재사용 결정`, `근거 누락`, `예상/실제 API 사용량`이다. 기준선 측정 전 효율 개선율을 마케팅 수치로 만들지 않는다.
