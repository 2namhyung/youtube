# Source assignment and planning review slice — 2026-10-13

## Objective / ownership

Let a Studio user assign an already registered local asset to another compatible requirement, detach a requirement without deleting files, and record separate source, rights and semantic review observations. This is planning review, NOT episode source approval or legal clearance. Actual render-preview remains blocked. Preserve the previous uncommitted worker slice.

One implementation writer owns narrowly scoped changes in `visualmaker/core/model.ts`, `director.ts`, `store.ts`, new source-review helpers, `jobs.ts` blocker disclosure if necessary, `src/app/api/studio/**` only as required, `src/components/studio/**`, Studio CSS, source review tests, package focused test inclusion and README/IMPLEMENTATION docs. No schema change is required if review records live in immutable Plan revisions.

Forbidden writes: `raw/**`, `video/**`, episode specs/state/generated files/approval markers, original youtube or 23jung checkouts, existing user data/assets/receipts, `youtube1/**`, `motion/**`. No physical deletion, production media generation, dependency installation, commit or push. One writer, no subagents.

## Data/API contract

- Keep `visualmaker-plan-v1` backwards-compatible. Optional `sourceReviews` is an append-only history in Plan snapshots; absent legacy fields must remain absent when validating older snapshots so worker snapshot hashes remain stable. Every record is planning-only, `productionAuthority=false`, `recordedBy=local-session`, not a claimed user production PASS.
- Review dimensions: `source`, `rights`, `semantic`; decisions: `pending`, `acceptable`, `rejected`. Require a bounded nonblank rationale even when resetting to pending. Generate ID/time/binding server-side. Do not mutate immutable Asset metadata or its upload receipt; Asset.status remains pending-review.
- Each event binds requirement ID, asset ID and exact SHA-256, and a deterministic context hash over requirement purpose/constraints plus all sharing scenes' narration, beat intent/role, relevant candidate meaning and selected direction. Never bind only the file or only the project revision: unrelated review events must not invalidate each other, but changed meaning/assignment must make old records stale. History stays visible; current decision uses the latest exact-context event for each dimension.
- Reassignment/detach must not resurrect an old acceptable assessment when returning to a previous asset. Invalidate current observations on assignment lifecycle changes; persist an assignment generation or explicit pending event(s) bound to the new context. Do not silently revive a formerly accepted context after changing narration and changing it back either; meaningful edits must durably invalidate affected assessments.
- `assign-asset`, `detach-asset`, `review-source` use existing transactional baseRevision PATCH. Verify local bytes and immutable receipts before recording or assigning. Stale tabs return409; requirements shared with any locked scene reject mutations. Validate requirement/asset presence, matching media type, evidence-only/focal prohibition, Omni PNG input restriction. Existing-asset assignment does not reupload bytes; detach keeps asset catalog/files/receipts and review history.
- Duplicate existing-file upload policy may remain unchanged; UI offers existing-asset assignment and explicit detach instead. Do not expand asset claims or bypass upload provenance. Captures/data stay evidence-only; no production-visible pixel use is introduced.
- Untrusted imported Plan JSON must not confer review decisions: new imported copies reset/drop sourceReviews and explain it. Old project revisions/jobs remain valid and immutable. No new API may accept raw attach-asset or caller-supplied review IDs/bindings as trusted.
- Requirements export and planning package retain these observations/context and explicitly pending production approval. UI labels distinguish missing/registered/recorded/rejected/stale; show three dimensions, reason/history, whole asset SHA and source/rights metadata, compatible reuse selector, detach and recording form. Do not label observation completion as source-ready, cut PASS or render authority.
- Do not implement or fake a renderer in this slice. Even all acceptable observations leave renderEligible=false / productionAuthority=false and require later episode adoption/source approval/style-frame gates. Avoid any auto-run upon review submit.
