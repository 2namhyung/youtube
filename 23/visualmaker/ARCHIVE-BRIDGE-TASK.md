# Archive candidate → Studio requirement bridge

## Purpose and ownership

One writer implements a real local archive-to-Studio attachment workflow, then independent execution verification and review. This is a step toward the complete tool, not a production approval or a completed rendering pipeline. Worktree: `youtube-visualmaker/23`.

Allowed edits: new `visualmaker/core/archive-candidates.ts`, scoped archive candidates/import API routes, `src/components/studio/archive-*`, narrow integration in Studio/CSS; shared upload/storage/model/director helpers only when required for consistent transactional ingest; focused tests, package test command, README/IMPLEMENTATION. Preserve unrelated changes. Root owns this task card until handoff; writer thereafter may clarify it. No redelegation.

Forbidden: changes to `raw/`, `wiki/`, `video/`, episode specs/state/generated/active roots/approvals, archive database schema or rows, collector code/collection runs, `.env*`, dependency install, network media fetch, commit/push/delete of user files, youtube1/motion. Fixtures exist only in freshly created temporary directories; never seed the actual archive or call `openArchiveDb()`.

## API/data contract

- GET `/api/studio/archive-candidates?id&baseRevision&requirementId&q&cursor` uses existing Studio local host/origin/token auth. Validate current Plan revision and exact requirement. Bounded parameterized local search (title/provider/query; explicit search is not semantic relevance), stable ID cursor, max 20 rows/page, bounded q length. Schema `visualmaker-archive-candidates-v1`: scope (project/revision/requirement/script hash), `productionAuthority=false`, `availability=available|unavailable`, candidates and next cursor. Missing DB is a usable unavailable state without creating any directory/database. Incompatible/malformed schema is distinguishable, safe error with no local path leakage.
- Read an already-existing configured `ARCHIVE_DB_PATH` or default `data/archive.sqlite` using `DatabaseSync` read-only + query-only, never archive opener/migrations/seeds. Fixed SQL over media_assets and graph_nodes. Server-only `ARCHIVE_RAW_ROOT` defaults to `data/raw`. No new cloud configuration.
- Candidate metadata: numeric archiveAssetId, title, provider/providerId, photo→image/video mapping, SHA256, bytes, MIME, duration, item/source URL, creator/publisher, license/attribution/rightsStatus/retrievedAt, compatibility and explicit blockers. Never expose local path, original media download URL, database contents outside this allowlist, arbitrary properties, or secrets. Escape text via React. Links only safe http/https without credentials. Do not load external thumbnails or automatic media downloads.
- POST `/api/studio/archive-import` accepts only `{id,baseRevision,requirementId,archiveAssetId,expectedSha256,semanticNote,evidenceOnly}`. No caller file path, URL, title/license rewrite, command/code, approval flag. Row is reloaded by ID; expected SHA binds the selection to current bytes. A malformed/missing hash, incomplete source/creator/license metadata, unavailable file, wrong media type, or generated-keyframe acquisition is blocked. Archive material cannot claim to be generated Omni keyframes.
- Revalidate revision and all affected locked scenes before copying/probing. Byte read is bounded <=40MB before allocation; metadata size and hash must match actual bytes. Require a regular file and reject symlink/junction/reparse components or escapes relative to the canonical configured raw root. Row paths are untrusted; no URL fetching, arbitrary filesystem reads, or evidence-only bypasses.
- Reuse actual image/video decode and Studio receipt validation. Store content-addressed Studio-owned bytes; resulting asset is always pending-review. Store server-derived source URL, creator, license+attribution+rights limitations as notes, exact archive asset ID/provider/original SHA and metadata fingerprint in receipt/optional typed provenance. evidenceOnly defaults true and data/screenshots remain evidence-only; human source/rights/semantic observations remain empty. Never import archive review_queue decisions as approval.
- Failure after validation/ingest (stale revision/locked/invalid Plan) must leave the Plan unchanged and remove only newly created owned receipt/temp objects. Never overwrite or remove pre-existing same-SHA assets/receipts. Atomic reuse must revalidate existing bytes. Shared upload helper improvements preserve existing upload behavior and tests.
- Successful response binds exact project/revision/requirement/archive ID/input SHA/resulting asset ID, `productionAuthority=false` and new Plan. Same-revision duplicate cannot create duplicate project mutations; stale retry is explicit409. No render/state advance or approval marker.

## UI story

Under a requirement's Sources controls, the user opens “수집된 자료 찾기”, searches local candidate metadata, reads provider/source/license and remaining restrictions, chooses a compatible candidate, writes semantic correspondence and purpose, and explicitly attaches it. Disabled controls for busy/locked/incompatible requirements. Show unavailable and empty states separately, clear errors and pending-review labels. Manual upload/reuse continue to work.

Scope requests by project/revision/requirement and token, abort on change/unmount, invalidate late list/import response; verify echoed scope/script hash/false authority and input/result binding before adopting Plan. Parent global busy owns import mutation; don't let stale project/scene responses switch current workspace. No server module imports into client. Use primitive effect dependencies and accessible named controls. Source review remains separate.
