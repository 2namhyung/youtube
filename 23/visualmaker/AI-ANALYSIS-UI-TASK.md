# Studio AI analysis request and review

Connect the verified local AI analysis API to Studio so users can explicitly request analysis and inspect segment-bound proposals. This is a review workflow, not automatic editorial adoption or production approval. The existing local rule-based proposal controls remain available and labelled separately.

## Frozen API contract

Use authenticated `x-visualmaker-token`, `cache:'no-store'`, AbortController and enforce response `Cache-Control:no-store`. Never import server SDK/SQLite modules into client runtime; type-only imports are permitted. Public records contain no keys or paths.

GET `/api/studio/ai-analysis?projectId=P&baseRevision=N` returns `{report}`. Report schema is `visualmaker-ai-analysis-readiness-v1`; scope includes projectId, revision, scriptSha256 and snapshotSha256 computed over `JSON.stringify(plan)`. Capability has available, modelId, reason, providerVerified:false; available means configuration/input readiness only. Limits are maxScriptUnits=20000, minSegments=1, maxSegments=40, minOutputTokens=512, maxOutputTokens=8192, minTimeoutMs=10, maxTimeoutMs=120000. Report includes up to 50 jobs, productionAuthority:false, requiresHumanReview:true, cost:'unknown'. Job fields: jobId, status, requestedRevision, snapshotSha256, scriptSha256, requestedModelId, requestContractSha256, createdAt, updatedAt, startedAt, finishedAt, attempt, externalCall:{startedAt,outcome}, error, artifact:null or {name:'ai-analysis-proposal.json',sha256}; report jobs additionally include stale. POST/GET proposal job lacks stale. Job status includes queued/running/succeeded/failed/cancelled/needs-review. One attempt only; retries forbidden.

POST enqueue exact body: `{action:'enqueue',projectId,baseRevision,idempotencyKey,expectedModelId,externalTransmissionConsent:true,billingConsent:true,maxOutputTokens,timeoutMs}` returns `{job}` with 201. POST `{action:'run'|'cancel'|'recover',projectId,baseRevision,jobId}` returns `{job}`, run=202, cancel/recover=200. Run requires current job revision/snapshot; cancel/recover may stop a stale owned job using current Plan revision. Generic jobs API hides/rejects AI jobs; this panel owns their controls. No retry command. Recovery may be rejected until server lease expiry; the DTO does not expose leaseExpiresAt, so do not fabricate a client eligibility timestamp.

GET same scope with `jobId` and `format=proposal` returns `{job,proposal}` only for succeeded current-scope job. Proposal schema `visualmaker-ai-analysis-v1`, requestId=jobId; exact scope, model:{adapter:'gateway-api-key'|'sdk-test',requestedModelId,responseModelId:string|null}, usage:{inputTokens:number|null,outputTokens:number|null}, cost:'unknown', productionAuthority:false, requiresHumanReview:true, records in exact Plan segment order. Each record: segmentId/mainMessage/uncertainty/visualMeaningBrief/searchBriefKo/searchBriefEn and source:{start,end,text,kind} derived from exact segment. All descriptive fields bounded 600 UTF-16 units; bounded source spans/text match Plan. `sdk-test` must be visibly labelled synthetic, never real AI quality evidence.

Client validates strict shape, supported enums and bounds, full current report/proposal scope hashes, job identities, exact segment bindings, unchanged authority and model/request correlation. Match proposal SHA-256 to job artifact using the server's compact `JSON.stringify(proposal)` artifact serialization with no trailing newline (`ai-analysis-job.ts` proposalBytes). Reject altered/missing/extra fields and stale/cross-project data; do not render it as current. Bound JSON response bytes before parsing (report can include 50 job records, proposal artifact<=200000 bytes; use reasonable explicit limits per mode).

## Interaction and state

Mount keyed by project ID/revision/script SHA/token so scope change clears consent, pending request identity, accepted job and proposal. Primitive effect dependencies; no mutation of Plan or locked scenes. Use dedicated report polling while queued/running; ignore aborted or out-of-scope late responses. Panel can receive Plan/token/busy; its own API report is the job authority, not generic jobs list. Place after main script/direction workspace and before render preparation panels. Defensively exclude AI kind from the generic execution list as well.

Show configured model, configuration-only status, call limits and unknown charge warning. Require separate explicit unchecked external-transmission and billing consent checkboxes before enqueue. Fixed valid defaults (e.g. 2048 output tokens, 60000ms timeout) may be editable within limits. No model/key/provider editing. Create and execute are separate explicit user actions; no automatic run or paid smoke request. Consent clears on scope change and after confirmed enqueue; queued job retains its already-bound consent. Prevent accidental double submission.

Retain the same idempotency key AND its complete request contract after ambiguous enqueue failure. Freeze model/limits/consent contract until outcome is reconciled; changing settings must not turn one ambiguous request into a fresh paid request. A successful validated enqueue may return an existing terminal job; acknowledge it, do not reset or run it again. Separate saved-job acknowledgement from subsequent report refresh failure. Run/cancel/recover failures cannot automatically create new jobs. Cancellation warning: remote processing/charges may continue; needs-review instructs provider processing/billing inspection before a separate new consent/request. Stale results cannot be inspected as current; stale queued/running jobs may be cancelled/recovered.

Render proposal records beside their exact source text: main message, uncertainty, visual meaning, Korean/English search suggestions. No claims of certified translation/source rights/grammar/production PASS. No auto-adoption button, stage marker or renderer trigger. Accessible field labels, status/alert regions and explicit button types; display generated strings as ordinary React text, never HTML.
