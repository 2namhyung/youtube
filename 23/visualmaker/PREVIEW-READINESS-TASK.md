# Preview readiness — read-only tool slice

## Scope and ownership

Studio must explain what prevents each planned scene from becoming a playable cut. This slice does NOT implement a renderer or generate pixels, approval markers, production assets, or episode changes. The current production catalog is empty; historical QA compositions cannot fill this gap. All reports remain productionAuthority=false, renderEligible=false, previewExists=false, eligibleForCutReview=false. Source observation records and manual narration timings are proposals, not production approvals.

One implementation writer owns core/preview-readiness.ts, its authenticated API, a small Studio panel/client, narrowly scoped Studio integration/CSS, focused tests/script, and README/IMPLEMENTATION addendum. Preserve all dirty changes. Forbidden writes: raw, wiki, video, episode spec/state/generated/catalog/approval markers, other projects/worktrees, production data. No dependency install, commit/push, or redelegation. Isolated temporary TEST plans only. Root and other agents are read-only until implementation handoff.

## API/data contract

- GET /api/studio/preview-readiness?id=PLAN_ID&baseRevision=N uses existing guard, validates exact nonnegative integer revision and current project identity. Missing/invalid 400, no auth 403, stale 409. No mutation, plan revision change, job creation or client paths. Return schemaVersion=visualmaker-preview-readiness-v1, projectId, revision, scriptSha256, snapshotSha256 of JSON.stringify(validated Plan), four fixed false authority/readiness fields above, renderer.status=not-implemented, and ordered scenes.
- Scene rows: sceneId, originCutIds, selectedCandidateId, mode or null, estimatedSeconds (explicit estimate), requirement rows, and stable structured blockers {code,message,requirementId?}. With no selected direction, show direction-not-selected and do not silently pick/render an alternative or union their requirements as selected. Only selected candidate requirementIds are evaluated; unused alternatives must not block selected requirements.
- Evaluate attached requirements using current reviewStates() exact asset/context hashes. List missing assignment, evidence-only visual input, media type mismatch, invalid dimensions/duration, missing/tampered local bytes (server-side bounded path/hash verification), and each missing/pending/rejected source/rights/semantic observation. Off-canvas evidence/data is not a visible asset and must not be marked missing visual dimensions. Report observations as observations, never human production approval. Asset count is unique SHA-256, not crops/IDs. No source photos automatically replace missing video, Remotion, or Omni modes.
- Every scene carries renderer-not-implemented and production-contract-not-bound blockers even if all planning observations are acceptable. Grammar is unverified by runtime Plan; record this separately for Remotion/Omni, do not infer valid operators or style/cut PASS. Narration recording/timing is OPTIONAL for provisional design and absence must NOT be a blocking condition. Existing scene estimate does not become measured cut timing. Do not read stale wiki/state strings as verified gates or pretend all EP001 cuts were inspected as active manifests.
- API report hashes bind plan snapshot, not independent production status. Local asset verification is a moment-in-time planning integrity observation only. No paths or token URLs in browser-visible errors. Authentication uses header token, never query token.
- UI button '미리보기 준비 상태 확인' fetches this report without enqueuing blocked jobs. Display non-production caveat, report revision, per-scene mode and actionable reasons; include loading/error/empty state. Report is invalidated on project/revision/script changes; abort late requests, validate response scope/hash shape/false fields, respect global busy. No PASS controls, playable video, placeholder imagery, or claims of rendering completion. Existing old blocked jobs remain readable; planning-package workflow stays unchanged.
