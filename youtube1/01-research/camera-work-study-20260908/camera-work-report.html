사건 재현 영상의 촬영·전환 설계

2026.09.08 · CinePrompt / 지정 YouTube 2편 / 공식 영상 생성 가이드 연구

권장 방식: 대본의 의미 → 공간 배치 → 샷 구도 → 상황 이미지 → 움직임 → 편집. 이미지에서 구도와 관계를 확정하고, 영상에서는 그 구도 안에서 일어날 행동과 카메라 이동을 지시한다. 10초 3샷은 유지 가능한 제작 옵션이지만, 세 이미지와 세 샷이 정확히 대응하는지는 별도로 확인해야 한다.

이 문서는 연구와 후속 설계 제안이다. 이번 연구에서는 새 이미지·영상을 생성하거나 기존 제작 계약·도구를 변경하지 않았다. 개선 효과의 정량 수치는 아직 측정하지 않았다.

1. 어디까지 확인했나

자료 확인 범위 해석의 한계
CinePrompt 실제 브라우저의 Single·Complex·Multi-Shot·Frame → Motion·Storyboard, 구도 선택에 따른 프롬프트 출력 유료 생성·참조 이미지 전송 결과는 시험하지 않음
편집루키 영상 공개 자동자막 처음부터 약 5분 36초까지, 마스크 시연 화면 표본 자동자막에 오인식이 있어 수치를 표준 설정값으로 채택하지 않음
뇽쌤필름 영상 공개 자동자막 처음부터 10분 09초까지, 설명의 챕터, 방향 일치·마스크 편집 화면 표본 약 10분 13초 영상의 마지막 음악 구간과 모든 프레임을 분석한 것은 아님
Google·Runway·Adobe 이미지 역할, 카메라 문법, 멀티샷, 공간 연속성 관련 공식 문서 모델별 안내를 다른 모델의 성능 보장으로 확대하지 않음

두 YouTube는 주로 장면 전환의 촬영·편집 방법을 다룬다. 구도·렌즈·카메라 움직임의 전체 교과과정은 아니므로 공식 촬영 자료로 보완했다.

3. CinePrompt를 어떻게 활용할까

실제 UI에서 확인한 역할은 다음과 같다. CinePrompt

모드 역할 우리의 사용법
Single / Complex 피사체·행동·환경·샷 크기·카메라 이동·렌즈·조명 등을 문장으로 조립 샷 설계의 누락 확인
Multi-Shot 공통 설정과 반복 요소를 정의하고 샷별 설명·카메라를 구성 세 샷의 목적과 움직임을 나란히 검토
Frame → Motion 이미지 설계와 움직임 프롬프트를 분리 검수한 상황 이미지를 영상화
Storyboard 격자 보드와 개별 프레임 확장, 영상화 경로 제공 전체 흐름 검토 후 개별 샷 이미지 확보

브라우저에서 Wide와 Static을 선택하고 추월 상황을 입력하자, 해당 촬영 용어가 붙은 짧은 프롬프트가 출력됐다. Frame → Motion 안내는 이미지가 시각 정보를 담으므로 움직임 지시는 짧게 쓰도록 설명한다. 생성 비용은 사용하지 않았다.

채택할 것: 이미지/움직임 분리, 공통 디자인 재사용, 샷별 구도 선택. 추가로 필요한 것: 대본 근거, 인물 좌석, 차량 앞뒤·방향, 샷 간 상태 연결 검수. 공개 UI의 태그와 구도 선택만으로 이 검수가 보장되지는 않는다. 격자 보드를 그대로 영상 입력으로 쓰기보다, 각 칸을 독립 이미지로 확보하는 방식을 우선 제안한다.

4. 카메라를 설계하는 다섯 질문

다음은 촬영 문법을 사건 재현용으로 정리한 설계 순서다.

  1. 무엇을 알게 할 것인가? ‘추월했다’, ‘딸이 동승했다’처럼 한 문장으로 쓴다.
  2. 무엇이 화면에 함께 보여야 하는가? 추월은 두 차량의 상대 위치, 모녀 소개는 두 좌석과 핸들이 필요하다.
  3. 어디에 카메라를 둘 것인가? 높이·방향·샷 크기를 먼저 정한다.
  4. 피사체와 카메라는 각각 어떻게 움직이는가? 두 움직임을 별도 문장으로 쓴다.
  5. 마지막 화면은 다음 샷과 어떻게 이어지는가? 위치·방향·시간·사건 단계가 연결되는지 확인한다.
구분 결정하는 것 예시
샷 크기 얼마나 보여주는가 와이드, 미디엄, 클로즈업
앵글 어느 높이·방향에서 보는가 아이레벨, 하이앵글, 탑뷰
구도 화면 안 어디에 놓는가 두 차량 모두 포함, 진행 방향 앞 공간 확보
카메라 이동 관찰 위치가 어떻게 바뀌는가 고정, 팬, 트래킹, 푸시인
렌즈·초점 공간감과 주목 대상을 어떻게 표현하는가 두 차량이 모두 선명한 심도

샷 크기·앵글·이동·초점은 서로 다른 선택이다. 클로즈업을 선택했다고 카메라가 가까워지는 동작이 생기는 것은 아니다. Runway 카메라 용어

정의는 Runway와 Adobe의 돌리 줌 설명을 참고했고, 적용 우선순위는 우리 영상용 판단이다. 매 샷에 이동을 넣을 필요는 없다. 움직임은 정보나 감정을 전달할 이유가 있을 때 선택한다. Adobe 트래킹 샷

카메라 브랜드·렌즈 제품명은 장면 배치를 대신하지 않는다. 실제 렌즈에서도 같은 초점거리의 화각은 포맷에 따라 달라진다. AI에는 숫자보다 ‘두 차량 전체와 사이 간격이 선명하게 보임’ 같은 관찰 가능한 결과를 우선 쓴다. ARRI 포맷·화각 설명

5. 우리 영상에서 먼저 바로잡을 것

공간 관계를 프롬프트보다 먼저 설계

앞서 저장한 첫 묶음 요청은 단일 referenceImageMediaIds 목록과 텍스트의 Reference 매핑을 사용했다. 각 샷의 시작 이미지를 시간 슬롯에 고정하는 구조는 그 파일에 없다. 따라서 ‘태그가 연결됨’과 ‘그 구도가 고정됨’을 같은 것으로 취급하면 안 된다.

좌석: 차량 기준 왼쪽 운전석과 화면 왼쪽을 구별한다. 앞유리 밖에서 실내를 보는 구도라면 운전자가 화면 오른쪽에 보일 수 있다. 핸들 위치와 손의 연결을 이미지에서 검수한다.

차량: 앞차·뒷차, 차선, 차량의 코가 향하는 방향, 이동 방향을 기록한다. 앞 범퍼가 앞차의 뒤 범퍼를 바라보는지 확인한다. ‘화면 왼쪽’만 반복하면 카메라 변경 시 오히려 모순이 생길 수 있다.

연속성: 같은 사건 구간에서는 카메라를 행동 축의 같은 쪽에 두는 것을 기본으로 한다. 반대쪽으로 바꾸면 화면상 진행 방향이 뒤집힐 수 있다. 변경이 필요하면 관객이 공간을 다시 파악할 구도를 먼저 보여준다. Adobe 180도 규칙, 이동 피사체의 축과 방향

이미지의 역할을 구분

입력 역할 의도 주의점

6. 보복운전 대본에 적용한 촬영 예시

아래는 확정 제작물이 아닌 연출 제안이다. 행동 묘사는 기사에 없던 새 사건을 추가하지 않아야 한다. 긴장은 얼굴 대신 몸의 자세·손·거리로 전달하되, 상징적 자세를 실제 관찰 사실로 표현하지 않는다.

샷의 의미 상황 이미지에 담을 것 카메라 핵심 행동
총기 형태 물건으로 위협 남성·물건·닫힌 운전석 창문을 한 구도에 배치 창문 높이 미디엄, 고정 물건을 한 번 들어 겨눔
모녀 동승 운전자인 어머니, 조수석 딸, 핸들, 벨트 앞유리 방향 투샷, 고정 작은 몸의 긴장; 다른 사건 추가 없음
앞을 막은 두 차량 짙은 차 앞, 밝은 차 뒤, 같은 방향과 차선 측면 하이앵글 와이드, 고정 뒤차가 멈춤
두 차선 진입 합류 시작 위치·두 차선 경계·뒤차 차선이 보이는 높은 와이드, 고정 밝은 차량의 연속 합류
경적 짙은 복장의 운전자 손과 핸들 중앙 손·핸들 인서트, 고정 손바닥으로 중앙을 누름
추월 같은 방향의 인접 차선, 짙은 차가 뒤에 있는 시작 두 차량 포함 측면 와이드 짙은 차가 앞으로 지나감

추월 샷에서 카메라가 짙은 차량만 따라가 밝은 차량을 놓치면 추월의 의미가 사라질 수 있다. 이 경우 고정 와이드가 유리하다. 카메라가 고정돼도 피사체가 움직이면 동적인 샷이다.

샷의 다양성은 드론·줌·회전을 번갈아 넣어서 만들지 않는다. 위 예시처럼 관계를 설명하는 와이드, 인물을 소개하는 투샷, 행동을 확인하는 인서트가 서로 다른 정보를 제공하도록 만든다. 이는 이번 대본에 대한 연출 판단이다.

7. 실제 제작을 위한 권장 순서

  1. 대본·음성 고정: 원문 문장과 실제 내레이션 구간에 샷을 연결한다.
  2. 전체 샷 목적 작성: 각 샷이 새로 알려주는 사실 한 가지를 쓴다. 생성 묶음 길이와 최종 편집 길이는 구별한다.
  3. 공간과 구도 작성: 좌석·차선·앞뒤·카메라 위치·동선을 정한다.
  4. 상황 이미지 제작: 해당 구도와 행동 시작 상태를 구현한다. 마지막 행동을 이미 끝낸 이미지가 아닌지 확인한다.
  5. 이미지 검수·애니매틱: 이미지를 내레이션 순서로 놓아 정보 중복과 설명 누락을 확인한다.
  6. 영상화: 피사체 행동과 카메라 이동을 짧게 지시한다. 복잡한 행동은 고정 카메라를 우선 검토한다.
  7. 샷 검수: 실제 움직임·인물·방향·대본 일치를 본다. 영상 파일이 생성됐다는 사실은 합격 근거가 아니다.
  8. 연결 편집: 하드컷을 기본으로, 의미가 필요한 지점만 전환을 적용한다. 승인 음성에 맞춰 편집한다.

이미지에서 시각적 오류를 고친 뒤 영상화하고, 움직임 지시는 간결하게 쓰는 접근은 Runway의 이미지→영상 가이드와 일치한다. 입력 이미지의 흐림·자세·방향 신호도 결과에 영향을 주므로 상충 여부를 확인한다. 단, Runway의 권고를 Omni의 동일 성능 보장으로 보지는 않는다. Runway 이미지→영상 가이드

Google은 타임스탬프로 여러 샷을 지시하는 예시를 제공한다. Omni도 복수 샷을 만들 수 있으며, 한 샷을 원할 때는 연속 샷임을 명시하도록 안내한다. 따라서 멀티샷을 불가능하다고 결론낼 근거는 없다. Veo 멀티샷 예시, Omni 프롬프트 가이드
