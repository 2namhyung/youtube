# Motion tool learning v4 — local discovery and fail-closed design

This directory prepares a layout-aware successor without modifying v3. It does not yet train or promote any tool.

The left side of a future comparison may be called an **OFFICIAL REFERENCE** only when exact official pre-rendered media is locally preserved and admitted with its bytes, upstream 40-hex commit, commit-pinned source URL, license bytes, and explicit license-review status. Source code, Lottie JSON, fixtures, templates, README screenshots, and locally invented semantic boards are not original rendered reference media. Production source-only examples are never executed; the narrow research-only source execution exception below does not turn a harness or derivative into an official original.

Current local discovery is intentionally blocked for all six tools. `lottie-web` distributes test animation JSON, but no admitted original render and no package `gitHead`. Motion Canvas distributes a commit-bearing core runtime but no example; its direct offline Node ESM import also fails on the installed package's `lib/meta` directory import, so the later learned-render path needs a separately verified local bundle boundary. GSAP, D3, dotLottie Web, and the FFmpeg runtime do not provide an admissible pre-rendered example tied to a mechanic.

Future scoring is defined by `layout-motion-score-v1.json`: geometry is 45 points and motion is 55 points. Passing requires at least 90/100 and at least 90% of each section, plus every anti-clone gate. The learned creator receives only derived numeric measurements and neutral-asset requirements, never reference pixels or source code.

Local-only audit commands:

```powershell
node studies/motion-tool-learning-v4/discover-local-official-examples.mjs
node studies/motion-tool-learning-v4/verify-local-discovery.mjs
```

No network, provider, upload, wiki promotion, or v4 sample rendering is authorized by this preparation stage.

## Research-only official source execution gate

Canonical production remains source-only. `motion-tool-learning-v4-research-official-render-v1` is a separate, non-promotable study boundary for rendering exact official examples. It requires an official repository and exact 40-hex commit, preserved and reviewed license bytes, a hash-complete dependency closure, a complete URL scan, external network blocking in a contained nonsymlink study root, an environment allowlist without credentials, and exact creator/verifier hashes. An allowlisted CDN-to-local replacement may change only the dependency locator, must use the same version, and records both hashes with `semanticChange=false`. The output is never story evidence, a production asset, engine authority, or wiki-promotion evidence.

Focused gate test: `npm run test:motion-tool-learning-v4`.

### Rejected false-positive research execution (append-only attempt k)

`motion-tool-learning-v4-research-gsap-lottie-k` passed only the obsolete v4 research-runtime and bbox/motion checks. Its GSAP and Lottie learned sides use generic purple primitives that do not preserve the reference component count, topology, contour complexity, color/area hierarchy, pairwise spatial relations, or occlusion/layer order. The high numeric scores are therefore false positives and not evidence of visual learning. The same rejection applies to `motion-tool-learning-v4-dotlottie-pilot-d` and `motion-tool-learning-v4-combined-review-c`; exact rejection bindings are in `motion-tool-learning-v5-v4-false-positive-rejection-a`.

v5 replaces this incomplete success definition. A result must independently score layout, motion and structure/style at least 90 each, weighted score at least 90, and pass every component/topology/contour/color-area/relation/occlusion/semantic/anti-clone hard gate. A single primitive cannot substitute for a multi-component or topologically different reference. Neutral paper-cut reconstruction must retain the same semantic object class and comparable silhouette complexity without copying official pixels.

Attempts b through j are retained as failed append-only roots. They failed before a verifier result (module global visibility in b; invalid learned Lottie wrapper/animation initialization in c-j) and are not success evidence. Attempt k remains `productionEligible=false` and `promotionEligible=false`; Motion Canvas, D3 and FFmpeg remain blocked by the recorded closure/original-visual requirements.

## Network-approved authority and honest pilot

`motion-tool-learning-v4-authority-b` preserves exact official GitHub raw bytes from six commit-pinned repositories and independently refetches every exact URL to detect drift. Downloaded example code, JSON, fixtures, and templates remain source-only and are not executed. Five tools therefore remain blocked without an admitted official pre-rendered visual. The sole locally preserved official motion artifact is dotLottie Web's commit-pinned `examples/web-node/demo.gif`; its license review is still pending.

`motion-tool-learning-v4-dotlottie-pilot-d` measured 180 official GIF frames and produced a blue rounded rectangle. Its former 98.811 score covered geometry/motion only and is rejected as a false positive because the learned primitive does not preserve the reference foreground structure and style.

This is not a successful one-tool feasibility pilot or curriculum. `promotionEligible=false` remains mandatory. Failed pilot-a/b/c and all later v4 attempts are preserved append-only.
