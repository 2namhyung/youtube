# Godot character skin system v1 (private contract)

This study defines a strict, front-view, Spine-like slot/attachment/skin contract for a reusable Godot 4 character. It is private and non-publishable. A skin is a set of independently hashed raster attachments bound to named bones; a flat full-character raster is never admitted.

The required semantic slots are `head`, `hair_back`, `hair_front`, `torso`, bilateral upper/forearms/hands, thighs, shins and feet. Every bone records joint/pivot coordinates, draw order and an allowed motion envelope. Articulating clothing slots must declare at least one physical `hidden-fill` attachment to cover exposed seams.

`validate-manifest.mjs` verifies containment, physical nonsymlink paths, bytes, SHA-256, PNG dimensions and alpha bounds, duplicate IDs/z-order, required slots, hidden-fill declarations, geometry compatibility and the single-raster rejection. `skin_loader.gd` is a Godot loader preflight only; it does not render or publish media.

The synthetic fixture is metadata-driven 4x4 RGBA PNGs generated by `create-fixture.mjs`. Existing generic-character A/B/flattened studies remain rejected history and are not admitted here.

The loader was executed successfully with the official portable Godot 4.7.1 stable build. Its preflight accepted 16 slots and 25 attachments with no warning or error. This proves contract loading only; it does not claim that synthetic squares are usable character art. Run `npm test`, `npm run validate`, and `npm run report` for the focused checks.
